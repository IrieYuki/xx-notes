# 网络安全工具速查笔记

## 怎么用这份文件

这份笔记覆盖**网络侦察与抓包**用到的基础概念和全部工具，供忘记时速查。
每条一个示例，示例下面的输出是**真的跑出来的**（在作者的 Mac + 自建靶场/Kali 上实测，2026-10），不是凭记忆写的。

- 零基础也没关系：第零章「基础概念」把 IP / 端口 / 协议 / DNS 这些名词先用大白话讲一遍，每章提到的名词在那里都能查到。
- 通用 Linux 命令（`ls` / `grep` / `chmod` / `ping` / `curl` / `ip` / `ss`…）不在这里，见《Linux 常用指令速查笔记.md》。
- 正文每条格式一样：**解析**（干什么 + 参数表 + 返回）／**操作**（示例 + 真实输出，一组一空行）／`> ⚠️ 提醒`（坑和易错点）。
- 会变的输出（IP、时间、包数）都标了「结构示例」：结构是真的，数字每次不同。
- **主动扫描（nmap/fping/arping）只打自己有授权的目标**——自己的靶场、自己的 Kali、CTF 平台。

## 章节顺序

零 基础概念 → 一 DNS 查询 → 二 域名注册信息 → 三 主机发现 → 四 端口扫描与指纹 → 五 抓包 → 六 过滤器 → 七 十六进制转换 → 八 Google Hacking

## 零 基础概念（给真小白）

### `网络` 两台设备怎么说话

**解析**　网络就是让不同设备互相传数据的一套系统。你手机看视频、电脑访问网站，本质都是把数据从一台设备发到另一台。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 主机（host） | — | 联网的机器：手机、电脑、服务器都算 |
| 数据包（packet） | — | 网络上传输的数据单位，像一封信：有收件人、有内容 |
| 带宽 | — | 网速，每秒能传多少数据 |

返回：概念

> ⚠️ 先把「网络 = 设备之间传数据」这个底子立住，后面所有工具都是在这个前提上做文章。

### `IP 地址` 每台设备的门牌号（IPv4）

**解析**　每台联网设备都有一个 IP 地址，像门牌号，数据靠它找到目的地。IPv4 是 4 个 0~255 的数字用点隔开（如 192.168.64.2），一共约 43 亿个。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| IPv4 | — | 现在最常见的一版（记：Internet Protocol version 4，网际协议第 4 版） |
| 127.0.0.1 | — | 回环地址：永远指向「自己这台机器」，本机测试专用 |
| 内网 IP | — | 家里/教室局域网里的地址，常见 192.168.x.x、10.x.x.x，外面的人连不进来 |
| 公网 IP | — | 全世界唯一的地址，运营商分配 |

返回：概念

**操作**

```bash
ifconfig lo0 | head -3
```
```text
（结构示例：每台机器接口名不同，重点看 inet 那一行就是 IP）
lo0: flags=8049<UP,LOOPBACK,RUNNING,MULTICAST> mtu 16384
	options=1203<RXCSUM,TXCSUM,TXSTATUS,SW_TIMESTAMP>
	inet 127.0.0.1 netmask 0xff000000
```

> ⚠️ 渗透里分清「目标的内网 IP / 公网 IP」是第一课：扫内网 IP 只在局域网里有效。

### `公网与私网` NAT：一个公网 IP 带全家上网

**解析**　家里所有设备共用一个公网 IP 上网，路由器用 NAT 把「内网地址 ↔ 公网地址」来回翻译。所以你自己看到的内网 IP 和网站上显示的你的 IP 不是一回事。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| NAT | — | 网络地址转换（Network Address Translation）：路由器替你做的内外翻译 |
| 局域网 | — | 家里/教室的私有网络，也叫内网 |

返回：概念

> ⚠️ 想知道自己的公网 IP，得问「外面的人」：dig +short myip.opendns.com @resolver1.opendns.com（需要外网；很多内网环境这个命令没响应是正常的）。

### `端口` 房间号：一台设备上的不同服务

**解析**　IP 找到设备，端口找到设备上的具体服务——像「大楼门牌号 + 房间号」。一台机器同时开网站、SSH、数据库，靠端口区分。端口号 0~65535，共 65536 个。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 端口 | — | 0~65535 的编号；服务默认用固定端口，但不是强制 |
| 监听（LISTEN） | — | 服务在某个端口上等人来连的状态 |
| 80 / 443 | — | 网页（HTTP / HTTPS，443 加密） |
| 22 | — | SSH 远程登录 |
| 3306 | — | MySQL 数据库 |

返回：概念

**操作**

```bash
nmap -sT -p 8081 127.0.0.1
```
```text
PORT     STATE SERVICE
8081/tcp open  blackice-icecap
```

> ⚠️ nmap 的 SERVICE 列是按端口号查表猜的名字，不是真实服务（8081 恰好叫 blackice-icecap）；想知道真实服务要用 -sV 去问。

### `常见端口速记表` 背下这几个就够入门

**解析**　端口号是「约定俗成」的默认值：服务可以开在任何端口，所以端口号 ≠ 服务，但先背熟常见默认值再谈其它。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 20/21 | FTP | 传文件（老协议，明文传输） |
| 22 | SSH | 远程登录（加密） |
| 23 | Telnet | 远程登录（明文，别用） |
| 25 / 110 / 143 | SMTP/POP3/IMAP | 发邮件 / 收邮件 |
| 53 | DNS | 域名解析 |
| 80 / 443 | HTTP/HTTPS | 网页（443 加密） |
| 3306 | MySQL | 数据库 |
| 3389 | RDP | Windows 远程桌面 |
| 8080 | HTTP 备用 | 常见于代理、测试服务 |

返回：对照表

> ⚠️ 记：端口是「门牌号」不是「身份证」——要确认真实服务，用 nmap -sV 去问。

### `协议` 通信的语言：大家按同一套规则说话

**解析**　协议就是设备之间约定好的「说话规则」：数据长什么样、谁先开口、怎么确认收到。渗透的本质就是看懂这些规则、找到没按规则设防的地方。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| TCP | — | 可靠传输（Transmission Control Protocol）：先建立连接、丢包重发，像寄挂号信 |
| UDP | — | 尽力传输（User Datagram Protocol）：直接发不确认，快但可能丢，像寄明信片 |
| HTTP | — | 网页传输规则，跑在 TCP 之上 |

返回：概念

> ⚠️ 扫描器扫端口，本质是探「目标在这个端口上说哪种协议的话」——所以扫描结果总是和协议绑定。

### `三次握手` TCP 建立连接的三步

**解析**　TCP 通信前要「三次握手」：SYN（我想连你）→ SYN+ACK（收到，可以连）→ ACK（好嘞，开始说话）。三步之后才传数据。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| SYN | — | synchronize：同步请求，第一步 |
| SYN+ACK | — | 对方同意：第二步 |
| ACK | — | acknowledge：确认，第三步 |
| 半开扫描 | — | 只发 SYN 不完成握手（nmap -sS 的原理） |

返回：概念

**操作**

```bash
tshark -r dvwa-demo.pcapng | head -3
```
```text
（结构示例：时间戳、端口号每次不同，三步结构不变）
1  0.000000  127.0.0.1 → 127.0.0.1  TCP 68 52131 → 8081 [SYN] Seq=0 …
2  0.000062  127.0.0.1 → 127.0.0.1  TCP 68 8081 → 52131 [SYN, ACK] Seq=0 …
3  0.000074  127.0.0.1 → 127.0.0.1  TCP 56 52131 → 8081 [ACK] Seq=1 …
```

> ⚠️ 抓包文件开头一定先看到这三次握手——下面这个例子就是抓「访问靶场 8081」时前 3 个包：SYN、SYN-ACK、ACK 正好三步。

### `HTTP 请求与响应` 打开网页时浏览器发了什么

**解析**　浏览器访问网页 = 发一个 HTTP 请求（要什么资源），服务器回一个响应（状态码 + 内容）。抓包看到的就是这些对话——HTTP 是明文，HTTPS 加了加密。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 请求 | — | 方法（GET 取页面 / POST 提交表单）+ 路径 + 头部 |
| 响应 | — | 状态码 + 正文 |
| 状态码 | — | 200 成功、302 跳转、403 没权限、404 没有、500 服务器炸了 |
| HTTPS | — | HTTP + TLS 加密：抓包只见密文 |

返回：概念

**操作**

```bash
curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8081/login.php
```
```text
200
```

> ⚠️ 404 ≠ 没有这个服务，只是没有这个页面；状态码是测试 Web 服务的第一眼情报。

### `DNS 是什么` 把域名翻译成 IP 的电话簿

**解析**　人记域名（baidu.com），设备只认 IP。DNS 就是中间的电话簿：你问「baidu.com 在哪」，它答「在 110.242.74.102」。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| DNS | — | Domain Name System，域名系统 |
| 解析 | — | 域名 → IP 的查询过程 |
| 解析服务器 | — | 替你查电话簿的服务器，一般是运营商或 8.8.8.8 这类公共 DNS |

返回：概念

**操作**

```bash
dig +short baidu.com A
```
```text
（结构示例：CDN 的 IP 池每次可能不同）
111.63.65.103
111.63.65.247
110.242.74.102
124.237.177.164
```

> ⚠️ 一个域名常对应多个 IP（CDN、负载均衡），每次查的顺序都可能不同——所以下面输出的顺序别较真。

### `域名结构` www.baidu.com 拆开看

**解析**　域名从右往左读：com 是顶级域 → baidu 是主域名 → www 是子域名。渗透里子域名是信息收集的金矿：很多子域名指向忘记维护的旧系统。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 顶级域 | — | com / cn / org 这类后缀 |
| 主域名 | — | 你在注册商那里买的部分，如 baidu.com |
| 子域名 | — | 主域名前面的部分，可以有很多层（a.b.baidu.com） |

返回：概念

> ⚠️ 子域名枚举是渗透信息收集的标配：公司官网安防再严，某个多年没人管的子域名可能就是后门。

### `DNS 记录类型` 电话簿里的不同条目

**解析**　DNS 不止「域名 → IP」一种条目，它有整本不同类型的记录，查询时要指定要哪一类。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| A | — | 域名 → IPv4（记：Address） |
| AAAA | — | 域名 → IPv6（比 A 长 4 倍，所以叫 AAAA） |
| CNAME | — | 别名 → 正式名（记：canonical name） |
| MX | — | 邮件服务器（记：Mail eXchange） |
| NS | — | 这个域名的权威 DNS 服务器（记：Name Server） |
| TXT | — | 任意文本：常用于域名验证、防伪造 |

返回：概念

**操作**

```bash
dig +short qq.com MX
```
```text
（结构示例：记录内容会变，结构不变）
30 mx1.qq.com.
10 mx3.qq.com.
20 mx2.qq.com.
```

> ⚠️ MX 前面的数字是优先级：越小越优先，邮件先发给 10 再考虑 30。

### `一次 DNS 查询的全过程` 从根服务器一路问到结果

**解析**　你问本地 DNS 服务器，它替你一层层问：根服务器（谁管 com？）→ com 的服务器（谁管 baidu？）→ baidu 的权威服务器（www 在哪？）→ 答案层层返回。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 递归查询 | — | 把活全丢给本地 DNS 服务器，它替你问到底（你平时用的就是这种） |
| 迭代查询 | — | 服务器一层层自己问过去 |
| 权威服务器 | — | 域名归属的最终答案持有者 |
| dig +trace | — | 把整个询问过程展示出来 |

返回：概念

**操作**

```bash
dig +trace baidu.com
```
```text
（未实跑：需要外网逐层查询；在自己机器上跑一遍能看到「根 → com → baidu」的完整链条）
```

> ⚠️ 渗透视角：谁控制了 DNS，谁就能把域名指到任意服务器（DNS 劫持）；dig 出来是 CDN 的 IP，真实源站藏在 CDN 后面。

### `打开一个网页发生了什么` 把前面全部串起来

**解析**　输入网址回车后：① DNS 解析域名 → IP　② 三次握手建立 TCP 连接　③ TLS 握手（如果是 HTTPS）　④ 发 HTTP 请求　⑤ 服务器响应　⑥ 浏览器渲染。渗透就是从其中某一步插进去偷看或冒充。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| DNS | — | 第 1 步：把域名变成 IP |
| TCP | — | 第 2 步：三次握手建连接 |
| TLS | — | 第 3 步：协商加密（HTTPS） |
| HTTP | — | 第 4、5 步：请求与响应 |

返回：流程

> ⚠️ 整条链每步都有对应的攻击面：DNS（劫持）、TCP（扫描、SYN 洪水）、TLS（证书伪造）、HTTP（SQLi/XSS，后面靶场实战讲）。

## 一 DNS 查询

### `dig` 查域名解析（DNS 查询首选）

**解析**　DNS 查询的标准工具：查域名对应什么 IP、什么记录。系统自带，功能最强。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 域名 | 必填 | 要查的域名 |
| 记录类型 | A | A(IPv4)、AAAA(IPv6)、MX(邮件)、NS(权威 DNS)、CNAME(别名)、TXT(任意文本)；不写默认 A |
| +short | 可选 | 只打印结果，不带注释和统计（脚本里取结果用它） |
| -x IP | 可选 | 反查：IP 对应的域名（PTR 反向记录，很多 IP 没配，返回空正常） |

返回：对应类型的解析结果

**操作**

```bash
dig +short baidu.com A
```
```text
（结构示例：CDN 的 IP 池每次可能不同）
111.63.65.103
111.63.65.247
110.242.74.102
124.237.177.164
```

```bash
dig +short qq.com MX
```

### `nslookup` 交互式查询（顺带看本机用哪个 DNS）

**解析**　另一个查询工具，输出更口语化；适合快速看「我这台机器在用哪个 DNS 服务器」。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 域名 | 必填 | 要查的域名 |

返回：解析结果 + 本机在用的 DNS 服务器

**操作**

```bash
nslookup baidu.com
```
```text
（结构示例：解析结果每次可能不同）
Name:	baidu.com
Address: 111.63.65.247
```

> ⚠️ 日常用 dig，nslookup 知道它存在就行。（记：nslookup = name server lookup，问域名服务器）

### `host` 一句话简单查询

**解析**　输出比 dig 更口语化的摘要：一次给出 A 记录和邮件服务器，适合快速扫一眼。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 域名 | 必填 | 要查的域名 |

返回：A 记录 + MX 记录等摘要

**操作**

```bash
host baidu.com
```
```text
（结构示例）
baidu.com has address 124.237.177.164
baidu.com has address 111.63.65.247
baidu.com mail is handled by 10 mx.maillb.baidu.com.
```

> ⚠️ （记：host = 主机，查「这个主机在哪、谁给它收信」）

## 二 域名注册信息

### `whois` 查域名注册信息

**解析**　查域名的注册商、创建/过期时间、NS、注册人。信息收集里用来给目标「画像」：什么时候注册的、背后是谁。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 域名 | 必填 | 要查的域名 |
| \| grep -iE '关键词' | 可选 | 过滤出想要的行（Registrar 注册商 / Creation 创建时间 / Expiry 过期时间 / Name Server） |

返回：注册信息摘要

**操作**

```bash
whois baidu.com | grep -iE "Registrar|Creation|Expiry|Name Server|Registrant"
```
```text
（结构示例：注册信息随时间变化）
Creation Date: 1999-10-11T11:05:17Z
Registry Expiry Date: 2028-10-11T11:05:17Z
Registrar: MarkMonitor Information Technology (Shanghai) Co., Ltd.
Name Server: NS1.BAIDU.COM
```

> ⚠️ 很多企业买隐私保护，查不到注册人也是信息（说明对方有安全意识）。whois example.com 只会返回 IANA 占位信息——example.com 是保留域名，查真实域名才有完整字段。（记：whois = who is，查「这域名是谁的」）

## 三 主机发现

### `arping` 查 IP 对应的 MAC 地址

**解析**　在同一局域网内查某个 IP 对应的 MAC 地址（物理地址）。比 ping 更可靠：主机很难挡 ARP。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| -c 2 | 可选 | 发 2 个包就停（不加会一直发，Ctrl+C 停） |
| IP | 必填 | 目标 IP，必须和你在同一局域网 |

返回：目标 IP 对应的 MAC 地址

**操作**

```bash
arping -c 2 192.168.64.2
```
```text
（结构示例：每次耗时不同，MAC 地址是 Kali 虚拟机的）
42 bytes from 4e:7d:ba:68:06:41 (192.168.64.2): index=0 time=370.000 usec
2 packets transmitted, 2 packets received, 0% unanswered
```

> ⚠️ 这就是 ARP 欺骗的物理基础：ARP 无认证，谁都能抢先回答「我是网关」，把流量骗到自己这里（中间人攻击）。（记：arping = ARP ping，用 ARP 协议代替 ICMP 的 ping）

### `fping` 批量扫一个网段里哪些主机活着

**解析**　ping 一次只能打一个 IP，fping 一次打整个网段，列出活着的主机。主机发现的标准起手式。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| -g | 必填 | 生成网段（记：g = generate） |
| -a | 必填 | 只显示活着的 IP（记：a = alive） |
| 网段 | 必填 | 如 192.168.64.0/24 |

返回：活着的 IP 列表（一行一个）

**操作**

```bash
fping -ag 192.168.64.0/24
```
```text
（结构示例：哪些机器开着每次不同）
192.168.64.1
192.168.64.2
```

> ⚠️ -a 与 -g 合起来 fping -ag 网段 就是「扫出这个网段有哪些机器」，渗透第一步。

## 四 端口扫描与指纹

### `nmap` 端口扫描与指纹（渗透神器）

**解析**　网络扫描的事实标准：扫目标开了哪些端口、跑什么服务、什么系统。练习扫 127.0.0.1 的靶场（8081-8085）。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| -sT | 二选一 | TCP connect 扫描：走系统完整三次握手，免 root，练习用它 |
| -sS | 二选一 | SYN 半开扫描：只发 SYN 不完成握手，更隐蔽，但要 root |
| -sV | 可选 | 探测服务版本（发探针读 banner） |
| -p 端口 | 可选 | 指定端口：-p 80,443 逗号分隔、-p 1-1000 范围、-p- 全部 65535 个 |
| --top-ports N | 可选 | 只扫最常见的 N 个端口 |
| -O | 可选 | 探测操作系统（需 root） |

返回：端口状态与（加了 -sV 时的）真实服务版本

**操作**

```bash
nmap -sT -p 8081-8085 127.0.0.1
```
```text
PORT     STATE SERVICE
8081/tcp open  blackice-icecap
8082/tcp open  blackice-alerts
8083/tcp open  us-srv
8084/tcp open  websnp
8085/tcp open  unknown
```

```bash
nmap -sS -p 8081 127.0.0.1
```
```text
You requested a scan type which requires root privileges.
QUITTING!
```

```bash
nmap -sV -p 8081 127.0.0.1
```
```text
PORT     STATE SERVICE VERSION
8081/tcp open  http    Apache httpd 2.4.25 ((Debian))
```

```bash
nmap -sV -p 22 192.168.64.2
```
```text
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 10.5p1 Debian 1 (protocol 2.0)
```

```bash
nmap -sT --top-ports 10 127.0.0.1
```
```text
（无开放端口 —— 本机靶场 8081-8085 不是常见端口，--top-ports 扫不到）
```

```bash
nmap -O 127.0.0.1
```
```text
TCP/IP fingerprinting (for OS scan) requires root privileges.
QUITTING!
```

> ⚠️ ① SERVICE 列是错的！nmap 默认只按端口号查 /etc/services 猜名字（8081 恰好叫 blackice-icecap），端口号≠服务，要真实服务加 -sV。② 版本泄露 = 攻击者直接查该版本 CVE、用现成 exploit 打，Shodan 甚至已经把全网跑特定版本的目标索引出来了。③ --top-ports 扫不到 8081-8085 这种非常见端口，要用 -p 显式指定。（记：nmap = network mapper，给目标网络画地图）

## 五 抓包

### `dumpcap` 抓包存文件（Wireshark 的抓包引擎）

**解析**　只负责抓包、存成 .pcapng 文件，不做分析，权限最低。配过滤器只抓想要的流量。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| -D | — | 列出本机所有可抓包的接口（macOS 是 en0/lo0/bridge100 这套，不是 eth0） |
| -i 接口 | 必填 | 在哪个接口抓：抓本机回环/容器流量用 lo0，物理 Wi-Fi 用 en0 |
| -f "过滤器" | 可选 | 捕获过滤器（BPF 语法，见第六章） |
| -w 文件.pcapng | 必填 | 存到哪个文件 |

返回：持续抓包，Ctrl+C 停止并报抓到多少包

**操作**

```bash
dumpcap -D
```
```text
（结构示例：接口列表因机器而异，重点找 en0（Wi-Fi）和 lo0（回环））
1. utun0
…
7. en0 (Wi-Fi)
…
11. bridge100
12. lo0 (Loopback)
```

```bash
dumpcap -i lo0 -f "tcp port 8081" -w dvwa-login.pcapng
```
```text
（结构示例：包数 = 你窗口内真实发生的流量数）
Capturing on 'Loopback: lo0'
Packets captured: 24
```

> ⚠️ 两个坑：① -w 目标文件已存在会被直接覆盖；② Ctrl+C 后看 Packets captured: N，N>0 才说明抓到了（0 = 目标流量没在窗口内发生）。抓包文件里全是明文凭据，这种文件永不入库（已写进 .gitignore）。（记：dumpcap = dump capture，把包「倒」进文件）

### `tshark` 读抓包文件、过滤、提取字段（Wireshark 命令行版）

**解析**　Wireshark 的命令行版：逐包打印、按条件过滤、只提取指定字段。适合在终端里分析抓包文件。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| -r 文件 | 必填 | 读哪个 .pcapng 抓包文件 |
| -Y '过滤器' | 可选 | 显示过滤器：抓完再筛（语法和 dumpcap 的 -f 不同，别混用） |
| -T fields -e 字段 | 可选 | 只提取指定字段（制表符分隔）；字段名 = Wireshark 里点开包看到的 Field Name |
| \| xxd -r -p | 可选 | 把十六进制的 http.file_data 转回明文 |

返回：包列表 / 过滤后的包 / 指定字段

**操作**

```bash
tshark -r dvwa-demo.pcapng | head -3
```
```text
（结构示例：时间戳、端口号每次不同）
1  0.000000  127.0.0.1 → 127.0.0.1  TCP 68 52131 → 8081 [SYN] Seq=0 …
2  0.000062  127.0.0.1 → 127.0.0.1  TCP 68 8081 → 52131 [SYN, ACK] Seq=0 …
3  0.000074  127.0.0.1 → 127.0.0.1  TCP 56 52131 → 8081 [ACK] Seq=1 …
```

```bash
tshark -r dvwa-demo.pcapng -Y 'http.request.method=="POST"' -T fields -e http.host -e http.request.uri
```
```text
127.0.0.1:8081	/login.php
```

```bash
capinfos dvwa-demo.pcapng
```
```text
（结构示例：数字随抓包内容变化）
File name:           dvwa-demo.pcapng
Number of packets:   24
File size:           5188 bytes
Capture duration:    0.043269 seconds
```

```bash
tshark -r dvwa-demo.pcapng -Y 'http.request.method=="POST"' -T fields -e http.file_data | xxd -r -p
```
```text
username=admin&password=password&Login=Login
```

> ⚠️ 常用字段：ip.src、ip.dst、tcp.srcport、tcp.dstport、http.host、http.request.uri、http.request.method、http.file_data、http.cookie。抓包 = 拿到明文口令的完整闭环，见下面最后一条。（记：tshark = terminal Wireshark；Wireshark = wire 网线 + shark 鲨鱼）

## 六 过滤器

### `BPF 捕获过滤器` 抓的时候只留想要的包

**解析**　捕获过滤器在抓包时就只留匹配的包（内核层丢包，省内存省磁盘）。语法给 dumpcap -f 或 tcpdump 用。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| tcp port 8081 | 常用 | 只要 8081 端口的 TCP 流量 |
| host 1.2.3.4 | 常用 | 只要和这个 IP 有关的包 |
| udp | — | 只要 UDP |
| and / or | — | 组合条件 |

返回：只抓匹配的包

> ⚠️ （记：BPF = Berkeley Packet Filter，伯克利包过滤器——加州大学伯克利分校发明的过滤语言）

### `Wireshark 显示过滤器` 抓完之后再筛

**解析**　显示过滤器对已抓到的包做筛选，只影响显示不影响文件。语法比 BPF 细，能直接点字段名（http.request.method 这种）。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| http.request.method=="POST" | 常用 | 只要 POST 请求 |
| ip.src==1.2.3.4 | — | 来源 IP 等于 |
| tcp.port==8081 | — | TCP 端口等于 |
| frame contains "admin" | — | 包内容包含某字符串 |

返回：只显示匹配的包

> ⚠️ 新手最该用的：Wireshark 里右键包 → Follow → TCP/HTTP Stream，把一次完整对话拼出来看。抓包分析一半的活靠这一招。

## 七 十六进制转换

### `xxd` 十六进制和文本互转

**解析**　把文本转成十六进制，或反过来。抓包里的 http.file_data 是十六进制，用它转回明文。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| -r | — | 逆向：hex → 文本 |
| -p | — | 纯 hex 输出（不带行号地址栏），正好和 http.file_data 的格式对上 |

返回：转换结果

**操作**

```bash
echo -n "hello" | xxd
```
```text
00000000: 6865 6c6c 6f                           hello
```

```bash
echo "68656c6c6f" | xxd -r -p
```
```text
hello
```

> ⚠️ （记：xxd = hex dump，十六进制转储——「x」形似 hex 的叉）

## 八 Google Hacking

### `搜索引擎语法` 用搜索引擎挖目标暴露的敏感信息

**解析**　不碰目标、只用搜索引擎语法就能挖出暴露的敏感页面和文件，属于被动信息收集。

| 参数 | 默认值 | 作用 |
|------|--------|------|
| site:xxx.com | 常用 | 只在目标站点内搜 |
| intitle:关键词 | — | 网页标题含关键词 |
| inurl:关键词 | — | 网址里含关键词 |
| filetype:扩展名 | — | 只要某种文件类型 |

返回：目标暴露的敏感页面/文件

> ⚠️ 经典组合：site:xxx.com filetype:xls "password"（泄露的密码表）、inurl:phpmyadmin（没设防的数据库后台）、site:xxx.com ext:sql inurl:backup（数据库备份）。语法也叫 Google dorking——dork 是俚语「呆子」，指被这些语法翻出来的没设防资源。

## 学习建议

1. 先背**三个区分**：被动 vs 主动（能否察觉）、`-sT` vs `-sS`（是否要 root）、捕获过滤器 vs 显示过滤器（语法不同）。
2. 信息收集的完整链路 = `fping -ag`（主机发现）→ `nmap -sT -p`（端口）→ `nmap -sV`（版本指纹）→ 查 CVE。
3. 每条命令都回自己机器上重跑一遍，输出对得上才算真会。
