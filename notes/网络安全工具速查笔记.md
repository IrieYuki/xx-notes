# 网络安全工具速查笔记

## 怎么用这份文件

这份笔记覆盖 **D2 抓包 + D3 信息收集** 学到的所有**安全/网络侦察工具**，供忘记时速查。
每条命令一个示例，示例下面的输出是**真的跑出来的**（在作者的 Mac + 自建靶场/Kali 上实测，2026-10），不是凭记忆写的。

- 通用 Linux 命令（`ls` / `grep` / `chmod` / `ping` / `curl` / `ip` / `ss`…）不在这里，见《Linux 常用指令速查笔记.md》。
- 正文每条格式一样：**签名**（怎么敲）｜**返回**（你会得到什么）｜**备注**（什么时候用、坑），下面接示例。
- `> ⚠️` 专门讲坑。**主动扫描（nmap/fping/arping）只打自己有授权的目标**——自己的靶场、自己的 Kali、CTF 平台。

## 章节顺序

一 DNS 查询 → 二 域名注册信息 → 三 主机发现 → 四 端口扫描与指纹 → 五 抓包 → 六 过滤器 → 七 十六进制转换 → 八 Google Hacking

顺序就是渗透信息收集的顺序：先被动（DNS/whois），再主动（主机发现 → 端口 → 指纹），抓包与过滤器是贯穿全程的基本功。

## 一 DNS 查询

### dig 查域名解析

**签名** `dig 域名 [记录类型]` ｜ **返回** 解析结果（默认 A 记录） ｜ **备注** 系统自带，功能最强

```bash
dig +short baidu.com A
```

```text
110.242.74.102
111.63.65.247
124.237.177.164
```

> ⚠️ 一个域名常对应**多个 IP**（负载均衡/CDN）。渗透里收集全 IP，是为了绕过 CDN 找到真实源站。

### dig +short 只输出结果（机器好读）

**签名** `dig +short 域名 类型` ｜ **返回** 只打印结果，不带注释和统计 ｜ **备注** 脚本里取结果用这个

```bash
dig +short qq.com MX
```

```text
30 mx1.qq.com.
20 mx2.qq.com.
10 mx3.qq.com.
```

> ⚠️ MX 前面那个数字是**优先级**，越小越优先（邮件先发给 `10 mx3`）。

### dig 记录类型 查 A MX NS 等各类记录

**签名** `dig 域名 类型 +short` ｜ **返回** 对应类型的记录 ｜ **备注** 常用：A(IPv4)、AAAA(IPv6)、MX(邮件)、NS(权威DNS)、CNAME(别名)、TXT(任意文本)

```bash
dig baidu.com NS +short
```

```text
ns4.baidu.com.
dns.baidu.com.
ns3.baidu.com.
ns7.baidu.com.
ns2.baidu.com.
```

> ⚠️ 经典低级错误是 **DNS 区域传送**：配置不当的服务器会允许 `dig axfr 域名` 把整张区域表吐给你。

### dig -x 反查 IP 对应的域名

**签名** `dig -x IP +short` ｜ **返回** 该 IP 的反向记录（PTR） ｜ **备注** 很多 IP 没配反查，返回空是正常的

```bash
dig -x 110.242.74.102 +short
```

```text
（空 —— 这个 IP 没配反向记录）
```

### nslookup 交互式查询

**签名** `nslookup 域名` ｜ **返回** 解析结果 + 用的是哪个 DNS 服务器 ｜ **备注** 适合快速看"我这台机器在用哪个 DNS"

```bash
nslookup baidu.com
```

```text
Address:	8.8.8.8#53        ← 本机在用的 DNS 服务器
Name:	baidu.com
Address: 111.63.65.103
```

### host 一句话简单查询

**签名** `host 域名` ｜ **返回** A 记录 + MX 记录等摘要 ｜ **备注** 输出比 dig 更口语化，适合快速扫一眼

```bash
host baidu.com
```

```text
baidu.com has address 111.63.65.247
baidu.com has address 111.63.65.103
baidu.com has address 110.242.74.102
baidu.com has address 124.237.177.164
baidu.com mail is handled by 10 mx.maillb.baidu.com.
```

## 二 域名注册信息

### whois 查域名注册信息

**签名** `whois 域名` ｜ **返回** 注册商、创建/过期时间、NS、注册人 ｜ **备注** 很多企业买隐私保护，查不到注册人也是信息

```bash
whois baidu.com | grep -iE "Registrar|Creation|Expiry|Name Server|Registrant"
```

```text
Creation Date: 1999-10-11T11:05:17Z
Registry Expiry Date: 2028-10-11T11:05:17Z
Registrar: MarkMonitor Information Technology (Shanghai) Co., Ltd.
Name Server: NS1.BAIDU.COM / NS2.BAIDU.COM / NS3.BAIDU.COM ...
Registrant Organization: 北京百度网讯科技有限公司
Registrant Country: CN
```

> ⚠️ `whois example.com` 只会返回 IANA 占位信息（example.com 是保留域名）。查真实域名才有完整字段。

## 三 主机发现

### arping 查 IP 对应的 MAC 地址

**签名** `arping -c N IP` ｜ **返回** 目标 IP 对应的 MAC 地址 ｜ **备注** 同一局域网内比 ping 更可靠（主机很难挡 ARP）

```bash
arping -c 2 192.168.64.2
```

```text
ARPING 192.168.64.2
42 bytes from 4e:7d:ba:68:06:41 (192.168.64.2): index=0 time=370.000 usec
42 bytes from 4e:7d:ba:68:06:41 (192.168.64.2): index=1 time=388.000 usec
--- 192.168.64.2 statistics ---
2 packets transmitted, 2 packets received, 0% unanswered
```

> ⚠️ 这就是 **ARP 欺骗**的物理基础：ARP 无认证，谁都能抢先回答"我是网关"，把流量骗到自己这里（中间人攻击）。

### fping -g 批量扫一个网段

**签名** `fping -g 网段` ｜ **返回** 网段内每个 IP 通不通 ｜ **备注** ping 一次只能打一个，fping 一次打一段

```bash
fping -ag 192.168.64.0/24
```

```text
192.168.64.1
192.168.64.2
```

### fping -ag 只列出活的主机

**签名** `fping -ag 网段` ｜ **返回** 只打印活着的 IP（-a=alive，-g=生成网段） ｜ **备注** 主机发现的标准起手式

> ⚠️ `-a` 只显示活的，`-g` 自动展开网段；两者合起来 `fping -ag` 就是"扫出这个网段有哪些机器"。

## 四 端口扫描与指纹

### nmap -sT TCP connect 扫描（免 root）

**签名** `nmap -sT -p 端口 IP` ｜ **返回** 端口开放状态 ｜ **备注** 走系统 connect() 完整三次握手，普通用户就能跑

```bash
nmap -sT -p 8081-8085 127.0.0.1
```

```text
PORT     STATE SERVICE
8081/tcp open  blackice-icecap
8082/tcp open  blackice-alerts
8083/tcp open  us-srv
8084/tcp open  websnp
8085/tcp open  unknown
```

> ⚠️ **SERVICE 列是错的**！nmap 默认只按端口号查 `/etc/services` 猜名字（8081 恰好在表里叫 blackice-icecap）。**端口号 ≠ 服务**，要真实服务见下一条 `-sV`。

### nmap -sS SYN 半开扫描（需 root）

**签名** `nmap -sS -p 端口 IP` ｜ **返回** 端口开放状态 ｜ **备注** 只发 SYN 不完成握手，更隐蔽，但要构造原始报文

```bash
nmap -sS -p 8081 127.0.0.1
```

```text
You requested a scan type which requires root privileges.
QUITTING!
```

> ⚠️ `-sS` 要 root 权限（构造 raw socket）。渗透里更常用（快、隐蔽、不留下完整连接记录），但练习用 `-sT` 效果一样。

### nmap -sV 探测服务版本（指纹）

**签名** `nmap -sV -p 端口 IP` ｜ **返回** 真实软件名 + 版本 ｜ **备注** 发探针读 banner，信息收集的临门一脚

```bash
nmap -sV -p 8081 127.0.0.1
```

```text
PORT     STATE SERVICE VERSION
8081/tcp open  http    Apache httpd 2.4.25 ((Debian))
```

```bash
nmap -sV -p 22 192.168.64.2
```

```text
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 10.5p1 Debian 1 (protocol 2.0)
```

> ⚠️ 版本泄露 = 攻击者直接查该版本 CVE、用现成 exploit 打。Shodan 甚至已经把全网跑特定版本的目标索引出来了。

### nmap -p 指定要扫的端口

**签名** `nmap -p 端口范围 IP` ｜ **返回** 指定端口的开放状态 ｜ **备注** `-p 80,443`（逗号分隔）、`-p 1-1000`（范围）、`-p-`（全部 65535 个）

### nmap --top-ports 只扫最常见的端口

**签名** `nmap --top-ports N IP` ｜ **返回** 最常见的 N 个端口状态 ｜ **备注** 快速摸底，别漏了非常见端口

```bash
nmap -sT --top-ports 10 127.0.0.1
```

```text
PORT  STATE  SERVICE
（无开放端口 —— 本机靶场 8081-8085 不是常见端口，--top-ports 扫不到）
```

> ⚠️ `--top-ports` 只扫最常见的端口（如 80/443/22）。非常见端口（8081-8085 这类）要用 `-p` 显式指定才扫得到。

### nmap -O 探测操作系统（需 root）

**签名** `nmap -O IP` ｜ **返回** 目标操作系统指纹 ｜ **备注** 和 -sS 一样需要 root

```bash
nmap -O 127.0.0.1
```

```text
TCP/IP fingerprinting (for OS scan) requires root privileges.
QUITTING!
```

## 五 抓包

### dumpcap -D 列出所有网卡

**签名** `dumpcap -D` ｜ **返回** 本机所有可抓包的接口列表 ｜ **备注** macOS 接口是 lo0/en0/bridge100 这套，不是 eth0

> ⚠️ **本机回环 / 容器流量抓 `lo0`**，物理 Wi-Fi 才是 `en0`。抓错接口 = 一个包都看不到。

### dumpcap 抓包 接口 过滤器 存文件

**签名** `dumpcap -i 接口 -f "过滤器" -w 文件.pcapng` ｜ **返回** 持续抓包，Ctrl+C 停止 ｜ **备注** 只抓包不做分析，权限最低

```bash
dumpcap -i lo0 -f "tcp port 8081" -w dvwa-login.pcapng
```

```text
Capturing on 'Loopback: lo0'
^C
Packets captured: 38
```

> ⚠️ 两个坑：① `-w` 目标文件**已存在会被直接覆盖**；② Ctrl+C 后看 `Packets captured: N`，**N>0 才说明抓到了**（0 = 目标流量没在窗口内发生，比如浏览器已经登录、不再发登录请求）。

### tshark -r 读抓包文件、逐包打印

**签名** `tshark -r 文件.pcapng` ｜ **返回** 每行一个包（时间、源/目的、协议、摘要） ｜ **备注** Wireshark 的命令行版

```bash
tshark -r dvwa-login.pcapng
```

```text
1  0.000000  127.0.0.1 → 127.0.0.1  TCP 68 49513 → 8081 [SYN] Seq=0 ...
5  0.005132  127.0.0.1 → 127.0.0.1  HTTP 784 GET /login.php HTTP/1.1
17 0.058598  127.0.0.1 → 127.0.0.1  HTTP 360 POST /login.php HTTP/1.1
```

### tshark -Y 显示过滤器（抓完再筛）

**签名** `tshark -r 文件 -Y '过滤器'` ｜ **返回** 只打印匹配的包 ｜ **备注** 和 dumpcap 的 -f（捕获过滤器）语法不同，别混用

```bash
tshark -r dvwa-login.pcapng -Y 'http.request.method=="POST"' -T fields -e http.host -e http.request.uri
```

```text
127.0.0.1:8081	/login.php
```

### tshark -T fields 只提取指定字段

**签名** `tshark -r 文件 -T fields -e 字段1 -e 字段2` ｜ **返回** 只输出指定字段的值（制表符分隔） ｜ **备注** 字段名 = Wireshark 里点开包底部看到的 Field Name

> ⚠️ 常用字段：`ip.src`、`ip.dst`、`tcp.srcport`、`tcp.dstport`、`http.host`、`http.request.uri`、`http.request.method`、`http.file_data`、`http.cookie`。

### capinfos 看抓包文件的基本信息

**签名** `capinfos 文件.pcapng` ｜ **返回** 包数、时长、文件大小等 ｜ **备注** 抓完先跑它，确认抓到了东西

### tshark … | xxd -r -p 把 POST 正文转成明文

**签名** `tshark -r 文件 -Y '...' -T fields -e http.file_data | xxd -r -p` ｜ **返回** 明文 POST 正文 ｜ **备注** http.file_data 出来是十六进制，xxd -r -p 转回字节

```bash
tshark -r dvwa-login.pcapng -Y 'http.request.method=="POST"' -T fields -e http.file_data | xxd -r -p
```

```text
username=admin&password=password&Login=Login&user_token=cfb14cfd0500de8e0f786d6493324142
```

> ⚠️ 这就是"抓包 = 拿到明文口令"的完整闭环。抓包文件里全是明文凭据，**这种文件永不入库**（已写进 .gitignore）。

## 六 过滤器

### BPF 捕获过滤器

**签名** `dumpcap -f "表达式"` / `tcpdump 表达式` ｜ **返回** 只抓匹配的包 ｜ **备注** 在内核层就丢包，省内存磁盘

| 表达式 | 含义 |
|---|---|
| `host 192.168.1.1` | 该 IP 收发 |
| `src host 1.2.3.4` / `dst host 1.2.3.4` | 只源 / 只目的 |
| `net 192.168.0.0/16` | 网段 |
| `port 80` / `tcp port 80` / `udp port 53` | 端口（可带协议前缀） |
| `tcp` / `udp` / `icmp` / `arp` | 按协议 |
| `tcp port 8081 and host 127.0.0.1` | 组合（and/or/not） |

### Wireshark 显示过滤器

**签名** `tshark -Y '表达式'` / Wireshark 过滤栏 ｜ **返回** 抓完再筛，只显示匹配的 ｜ **备注** 语法比 BPF 细，能点字段名

| 过滤器 | 含义 |
|---|---|
| `http` / `http.request` / `http.response` | HTTP 请求/响应 |
| `http.request.method == "POST"` | 只看 POST（登录/上传） |
| `ip.addr == 192.168.64.2` | 与某 IP 通信（src/dst 都算） |
| `ip.src == 127.0.0.1 && tcp.port == 8081` | 组合（`&&` 与、`\|\|` 或、`!` 非） |
| `tcp.flags.syn == 1` / `tcp.flags.reset == 1` | 握手包 / RST |
| `tcp.stream eq 0` | 第 0 条 TCP 流 |
| `icmp` / `arp` / `dns` | 按协议 |
| `http contains "password"` | 内容含关键词 |
| `tls.handshake.type == 1` | TLS ClientHello（HTTPS 只看得到这层） |

> ⚠️ 新手最该用的：Wireshark 里右键包 → **Follow → TCP/HTTP Stream**，把一次完整对话拼出来看。

## 七 十六进制转换

### xxd 十六进制和文本互转

**签名** `echo -n 文本 \| xxd`（→hex）／ `echo hex \| xxd -r -p`（→文本） ｜ **返回** 转换结果 ｜ **备注** `-r` 逆向、`-p` 纯 hex（无地址栏）

```bash
echo -n "hello" | xxd
```

```text
00000000: 6865 6c6c 6f                           hello
```

```bash
echo "68656c6c6f" | xxd -r -p
```

```text
hello
```

> ⚠️ tshark 的 `http.file_data` 输出正好是 `xxd -p` 格式，所以管道接 `xxd -r -p` 直接转明文。

## 八 Google Hacking

### 搜索引擎语法

**签名** 在搜索引擎里用 `site:` `intitle:` `inurl:` `filetype:` 等 ｜ **返回** 筛出目标暴露的敏感页面/文件 ｜ **备注** 被动收集，不碰目标

| 语法 | 作用 | 例子 |
|---|---|---|
| `site:xxx.com` | 只搜某域名下 | `site:baidu.com` |
| `intitle:"admin"` | 标题含某词 | `intitle:"后台管理"` |
| `inurl:admin` | URL 含某词 | `inurl:login.php` |
| `filetype:pdf` | 只搜某类型 | `site:xxx.com filetype:pdf` |
| `ext:sql` / `ext:bak` | 备份文件 | `site:xxx.com ext:bak` |

> ⚠️ 经典组合（敏感信息泄露）：`site:xxx.com filetype:xls "password"`（泄露密码表）、`inurl:phpmyadmin`（没设防的数据库后台）、`site:xxx.com ext:sql inurl:backup`（数据库备份）。

---

## 学习建议

1. 先背**三个区分**：被动 vs 主动（能否察觉）、`-sT` vs `-sS`（是否要 root）、捕获过滤器 vs 显示过滤器（语法不同）。
2. 信息收集的完整链路 = `fping -ag`（主机发现）→ `nmap -sT -p`（端口）→ `nmap -sV`（版本指纹）→ 查 CVE。
3. 每条命令都回自己机器上重跑一遍，输出对得上才算真会。
